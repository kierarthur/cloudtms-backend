## Gate and nullable semantics

Save produces an immutable version; assignment references that exact version from a future, unfinalised cycle. Both leave the feature off. A NULL assignment clears rules for the later range and always gives NULL effective rules. It may also carry the enabled SIGNED_CHECK_ONLY purpose after root's separate proof gates; no self-bill or agency version is forced onto a signed group. NHSP new rules are refused.

`weekly_source_is_import_authoritative_v1` checks the unchanged effective ROSTER + SOURCE_AUTHORITY + CHECK_ONLY pair, with a membership precheck so an ordinary/unassigned client returns false. `weekly_source_has_self_bill_rules_v1` follows the literal plan contract: effective rules IS NOT NULL, including an enabled agency version. **Every self-bill-only consumer must additionally require `values.invoice_sender='CLIENT_SELF_BILL'` before any effect.** F2 was sent this exact contract.

Effective rules read only an enabled RULE_SET assignment of the cycle's group/date, with exact Client membership and same-agency/environment immutable version. Otherwise they are NULL; no rule setting or version enters policy_sha256 or NO_CHANGE. Final INSERT freezes the exact enabled version; UPDATE cannot alter or backfill that witness. Disabled and NULL assignments keep legacy NULL.

The agency predicate resolves a current, unarchived, nonrevoked physical Weekly Timesheet, actual Contract/client/week, its dated ROSTER cycle/assignment and enabled AGENCY_INVOICE version. It requires SOURCE_AUTHORITY/CHECK_ONLY/non-self-bill, raw/effective Contract self-bill/no-Timesheet/NHSP refusals, client no-invoices refusal, exact current financial-client/version compatibility and frozen client compatibility. The signed predicate shares actual physical/date/membership scope, accepts nullable-Contract Daily only from one current same-version TSFIN client, requires enabled SIGNED_CHECK_ONLY with NULL version, exact TIMESHEET_AUTHORITY/INVOICE_EVIDENCE_REQUIRED and existing VALIDATION_ONLY route core. It proves scope; the caller must still prove the finalized manager signature. Both helpers were sent to the credit and D10 lanes.

Activation requires active admin, exact agency/group/assignment/date/version, explicit boolean/purpose, request id/reason and the actual latest release row being VERIFIED with equal repository/installed contract hashes. An APPLYING or FAILED successor holds activation. Receipt, timestamp, actor and reason live in the assignment. No release-ledger row is fabricated or written. Root alone may call it after all financial, security, document, Office/MyTMS and NEXT gates for that group.

Agency activation additionally requires an exact Client settings-CAS manifest (at most 100 dated members), takes Client owner gates before group locks, locks current Client/settings/Contract rows, flips the assignment and invokes the existing Client setup owner in the same transaction. It preserves other settings and records before/after values, IDs and CAS hashes. Any refusal or failure rolls back the gate and policy together. Disable restores prior values through that owner only if both the supplied CAS and stored after-CAS match; it refuses stale changes or an already-past restoration date rather than overwriting history or leaving SOURCE policy without its gate. Clipping an enabled agency assignment is likewise refused until a reviewed atomic transition. A later scheduled Client-policy boundary in an agency range is explicitly refused by the bounded activation owner.

The one group gate exposes all later consumers using RULE_SET or SIGNED_CHECK_ONLY scope for that group. Saving configuration never constitutes permission to expose those consumers.
