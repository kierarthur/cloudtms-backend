# Correction consumer wire audit

Controlling input is root's current `broker/src/timesheet-correction-orchestrator.mjs`, SHA `637c3b206b8e6700ce40e6ea9e5209bab8fb1b0702322375505a9750f1989f23`. The proposal preserves root's complete 1649 decimal-text request-authority decoder and all 32 callback tests. Exact other source hashes are in `CN_WIRE_SOURCE_GUARD.json`. These are saved-source identities, not installed PostgreSQL hashes.

Two real producer/consumer mismatches are corrected in the complete proposed module and minimal guarded `CN_WIRE_ROOT.diff`:

- Native `correction_id` is **TEXT** `awc:<immutable root UUID>:<request UUID>`. It is not a UUID. The proposed receipt guard validates its exact closed form and binds the request component; with a prepare context it also binds the immutable root. Prepared P0 must carry that same request/root identity before canonical production.
- Native `target_revision` is **TEXT** SHA-256, created by Send from immutable request/original/proposal facts. It is not an incrementing integer. Both fresh Send and PREPARE require canonical 64-character lowercase hex. Optional terminal replay witnesses, if supplied, must keep the same native type; proposal revision stays the integer constant 1.

## Meaningful source vectors and remaining proof

`tests/healthroster-f4-ai-correction-wire.test.mjs` retains the existing 32 cases with actual native TEXT correction IDs, SHA target witnesses and signed-witness field names. Five additional cases prove unsigned agency origin, numeric/malformed/coercible witness refusal, request/root mismatch, foreign APPLIED replay and supplied terminal witness negatives. All 37 pass. They include real closed callback contracts but explicitly use synthetic snapshots/RPC responses, so they are not SQL approval, document, phone, credit-note or native financial acceptance.

Root integration must compare the exact controlling module SHA before applying the minimal diff, then re-run the current callback suites and native correction journeys. Full signed weekly/DAILY A0/A1/D1/I1, repeated correction, cancellation/recovery, immutable original/issued I1 support, native negative R0 finance, P0 normalisation, exact complete-unit approval and credit-note/return placement remain acceptance gates. No shared/runtime/frozen Protection52 source, SQL, route, database, Git or hosted state was changed by this proposal.
