The caller uses `public.weekly_source_checklist_submission_manifest_v1(jsonb)` with actual actor, bounded limit 100 and only the native returned cursor. It reads all missing rows at one binding/revision/count before any write, checks scalar native hashes and immutable Candidate workflow/component/signature or native document witness identity, genuine Client/week→native-Sunday mapping, increasing unique Timesheet IDs and complete missing count. Changed actor/binding/revision, unsupported witness, duplicate/repeated cursor, invalid or incomplete pages and an explicit operational capacity overrun refuse before the first writer. The default capacity is 10,000 entries, configurable up to 100,000; it is a fail-before-write work bound, not a calendar lookback or permission to omit a lawful old week.

It writes a new `manifest.json` with exclusive-create semantics, fsync and a fresh saved-byte SHA-256 before the first metadata RPC. Each actual Timesheet then gets exactly one sequential `public.weekly_source_checklist_historical_prepare_atomic_v1(jsonb)` call carrying actual actor/Timesheet IDs and the literal native submission/admission hashes. Each returned actual cycle receipt is validated against the complete original row and saved separately before another writer. Multiple Timesheets in the same Client/week may reuse the first genuine cycle, without manufacturing a new ID or completion.

A transport or invalid-response failure is `UNCONFIRMED`: the native transaction may already have committed. The caller preserves earlier confirmed receipts, saves that unknown outcome, stops and never retries it or an earlier business save. A receipt-persistence failure stops before any later writer and returns the actual confirmed/unknown outcome and counts in memory; it never claims rollback. A fresh replay uses a fresh manifest/run directory and therefore omits cycles that genuinely became present. Existing manifest/receipt paths are never overwritten. A final fresh native origin census must report missing count zero; new missing work or unavailable verification keeps readiness false. `qualification=false` is unconditional: a prepared metadata census is not Checklist/API/UI/financial/feature qualification.
