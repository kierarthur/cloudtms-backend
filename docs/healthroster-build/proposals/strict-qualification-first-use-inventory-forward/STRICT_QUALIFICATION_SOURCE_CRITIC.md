## Finding 1 — P1: the new OPEN/CLOSE/REVOKE owner repeats the forbidden JSON concatenation form

`Q45/TEST_JOURNEY_SCOPE.sqlinc:121`, in `private.weekly_source_protected_test_setup_atomic_v1(jsonb)`, contains:

```sql
perform pg_advisory_xact_lock(hashtextextended('weekly-source-test-journey:'||auth->>'scope_id',0));
```

The concatenation must extract text first: `'weekly-source-test-journey:' || (auth->>'scope_id')`. PostgreSQL places both operators in its same left-associative operator tier, so the current expression groups the concatenation before `->>`, rather than building the intended text lock key. This is the exact `prefix || item->>'key'` first-use regression forbidden by repository AGENTS after the Rota failure. The parser's precedence/associativity is documented in [PostgreSQL 17, operator precedence](https://www.postgresql.org/docs/17/sql-syntax-lexical.html#SQL-PRECEDENCE).

**Consequence:** a valid setup request reaches this expression before the OPEN/CLOSE/REVOKE branch or audit write. The new cross-session admission path cannot be accepted merely because its PL/pgSQL definition compiles. The source inference is an invalid first-use expression; this critic did not execute it or observe a native SQLSTATE.
