# One planned agency T0 change owner — source design for independent review

The primary v2 plan §26.5.1 specifies `public.weekly_source_agency_timesheet_change_v1(p_contract_week_id,p_reason,p_expected_signature,p_request_key,p_actor_user_id)`, replay-safe by request key, with its request row holding T0→D1 during an interrupted same-draft round trip. §25.2 specifies the only private wrapper `weekly_source_agency_draft_round_trip_v1(text,text,uuid)` and forbids caller invoice/line/Timesheet/payload choices or general invoice-editor widening. Root clarified on14October that “no new change store” forbids a shadow/duplicate store, not this ONE precisely justified planned request owner. Implementation is held for this independent design review.

The actual source census finds no agency T0 change owner or its planned request row. Existing `private.weekly_source_agency_invoice_check_only_v1(uuid)` is a strict current configuration/origin predicate, not a change, authorise, validation, issue-close or week-complete writer. Current `timesheet_correction_send_v1` implements whole issued-origin R0/P0 and signed check-only corrections; it must not stand in for preset T0 alignment. Its AGENCY_INVOICE_CORRECTION arm requires an ISSUED/PAID parent. The actual generic invoice editor retains its service-role branch exactly, so the bounded wrapper requires no impersonation, GUC or change to general invoice editing.

## Single private row authority

Proposed sole table: `private.weekly_source_agency_timesheet_change_requests`. Logical audited postgres ownership; no direct PUBLIC/anon/authenticated/service_role access. Only finite source-owned SECURITY DEFINER creators/readers/phase owners may write it. No schedule, signature, query, financial, authorisation, renderer or job store is copied. Existing SQL/business owners and the actual Worker recompute remain call-only.

Immutable identity fields are request UUID/key and complete request digest; real Office actor; actual native agency; Contract-week/Contract/Candidate/Client; actual source group/cycle/accepted publication/upload/current rule-version and source-CAS identities; initial current T0 UUID/version/current row signature and canonical family identity; initially observed original unissued D1 UUID/number or null. Those facts come from native current owners under their locks and never from browser actor/T0/D1/line/payload choices. Caller fields are only the plan's Contract-week selector, bounded reason, expected current signature and stable request key. A global unique request key plus full actor/input digest refuses a conflicting replay; a request key never adopts a different actor or T0.

Lifecycle fields are row phase/version; actual-current T0/version/signature after each accepted native step; nullable retained D1 return-hold state; finite actual native owner receipts and hashes; actual TSFIN outbox identity/reason and current financial-row/version proof; last definite refusal; real created/updated/completed actor/time. The current ordinary Worker leases actual `ts_financials_outbox.id` and returns processed counts/current completed Timesheet IDs; it supplies no separate durable run/task identity, so this owner will not invent one. Receipts are bounded typed data emitted by the owners, not caller annotations. Receipt hashes prove retained bytes but do not by themselves admit an operation. Original source/input/T0/D1 facts are immutable; lifecycle writes use locked row phase/CAS and only validated real before/after results. One ACTIVE request per actual canonical family prevents competing amendments. No physical destructive-delete or unproved terminal receipt path is offered.

States are ACTIVE and COMPLETED; a definite failed step keeps ACTIVE at its last genuinely completed phase with a closed native refusal. No fake FAILED→COMPLETED transition, “prepared” flag or caller-owned readiness state is admitted. Replay of COMPLETED returns the exact recorded complete receipt. A genuine interrupted ACTIVE request resumes only its own actual phase and same immutable T0 family/D1. A current source/row/actor mismatch refuses before the next step; no silent overwrite or adoption of a new source capture is allowed. Any later explicit supersession policy must be separately reviewed; it is not included as an escape hatch.

## Actual phase boundaries

| Recorded phase | Required actual native proof before recording | Next operation |
|---|---|---|
| CAPTURED | Genuine current Contract-week/T0/family/Candidate/Client, expected row signature, actual dated preset/rule/Source feature/qualification and current publication/CAS, real active pay actor, exact initial invoice placement; no issued parent | Remove only T0 from its original unissued D1 if present; otherwise proceed to ordinary unauthorise/edit |
| DRAFT_REMOVED | Unchanged invoice_apply_edits exact remove payload derived from all T0 lines on D1; every T0 line removed, D1 ID/number and unrelated lines equal; existing locks/CW state checked | Existing ordinary unauthorise when required; preserve amounts already paid |
| UNAUTHORISED | Actual ordinary owner complete receipt and real current T0/version/signature; no remaining invoice placement | Existing contract_week_manual_upsert_atomic with schedule selected only from genuine finalised native source rows |
| SCHEDULE_APPLIED | Actual existing edit owner receipt, fresh physical current T0 and full unchanged source-CAS/family identity | Existing enqueue_ts_financials and Worker targeted runTsfinWorkerOnce on that exact T0 |
| RECOMPUTE_PENDING | Actual outbox UUID, exact T0 and native reason from existing queue; not an invented run/task, prepared or READY flag | Worker executes existing canonical producer/writer; the exact native request rechecks output on resume |
| FINANCIAL_CURRENT | Actual writer result/current TSFIN UUID/T0 version/native authority and required policy/source/component identities; native NEXT fresh-TSFIN admission test | Scoped authorise wrapper calls existing segment-update owner, unchanged ordinary authorise and single validation writer |
| AUTHORISED | Full native authorise result, recorded real clicked actor, actual current row/finance/validation and protected-position/source state | Return only this actual T0 to original D1 through the bounded wrapper if present |
| COMPLETED | Full required action succeeded, complete current source/row/financial/authorisation proof, D1 exact complete placement or lawful no-D1 case, unrelated lines and D1 number equal, genuine audit | Exact idempotent replay only |

The Worker starts and advances the same finite native request, executes actual existing recompute inline for only its recorded T0, then asks the same native owner to rederive the resulting phase. A native reply requiring recompute is pending, never a completed action. A failed or stale recompute returns the plan's AGENCY_INVOICE_TSFIN_NOT_READY/current native refusal. No second calculator, financial writer, authorisation engine, fake job result or normalized browser financial payload is added. Native SQL cannot pretend that a JavaScript recompute already ran.

The public five-argument owner has no caller phase selector. On first admission and on exact replay it advances only the next native-validated phase until recompute is necessary or the actual action is complete. The trusted Worker calls the existing targeted recompute and repeats the same five arguments; it never posts an asserted result, source schedule, finance snapshot, job success or phase. A crash before a transaction commits records no phase. A crash after it commits uses that recorded phase's native postconditions on replay; if those no longer hold, the request remains ACTIVE with its real last phase and return hold. DA-6 explicitly allows a truthful recoverable hold. Newer import/source CAS is never silently adopted by a partly executed click, and an old source capture is never relabelled current. This proposal offers no force-complete, cleanup expiry, new-key takeover or actor impersonation; a source conflict is an explicit recovery dependency needing a reviewed native policy before a new economic target is accepted.

## Narrow R239 invoice wrapper and current guards

`private.weekly_source_agency_draft_round_trip_v1(p_request_key text,p_step text,p_actor_user_id uuid)` admits REMOVE/RETURN only for the exact genuine ACTIVE row and its real clicked actor. It reuses the native active admin/pay-authoriser/golden-key predicate and actual dated Source/preset/check-only route/subject authority, resolving current T0/family again. It locks the recorded original unissued INVOICE DRAFT/ON_HOLD D1 and request in the actual current lock order. It refuses a foreign family/actor/request, changed signature/source, another draft, issued/paid D1, other return holds and unproved full component placement.

The wrapper constructs only remove_invoice_line_ids for all genuine T0 lines on recorded D1, or add_timesheet_ids=[recorded current T0] for RETURN. It calls unchanged invoice_apply_edits through the actual service path, then independently rederives D1/number/unrelated-lines/full T0 placement before recording success. Caller cannot choose D1, T0, line IDs, prepared finance or payload. General invoice-edit routes remain admin-only. Signed request-bound P0 recovery keeps its existing immutable correction store and separate genuine APPLIED/native-placement authority; it does not create an agency ACTIVE request to impersonate this T0 workflow.

R239 includes signed check-only Weekly and Daily recovery. Existing W14/W15 `weekly_source_office_authorise_scope_v1` is deliberately a Weekly/HOURS scope; its false result cannot admit a non-admin Daily actor or be treated as proof that Daily is unrelated. The signed recovery arm must instead rederive the existing `weekly_source_signed_check_only_v1` predicate, real signed correction origin/witness, original client/work date and actual dated Office authority from the stored request, then resolve and validate its exact P0. It stays inside the existing correction request owner and same-D1 Return operation. It grants no ordinary Daily authorise/editor capability, and introduces no second correction or agency request. The preset T0 owner remains Contract-week based and uses the existing W14/W15 Source probe before its native mutations.

Each public service entry explicitly refuses non-READ-COMMITTED transactions before its own reads/writes and needs the real supported top-RPC/role/session proof. Request-specific A0 fences do not establish safety for a hidden request in a pre-existing repeatable-read snapshot. Complete owner/trigger composition must protect the same current T0 from foreign mutations while ACTIVE using actual canonical family/Contract-week/invoice locks and request-row postconditions; no generic GUC or caller context unlock is allowed. Existing ordinary, Candidate, NEXT, WP-PP, Report and C1 hooks remain part of every full current-owner reverse. The native concurrent schedules remain mandatory even after these source guards are written.

While a real return hold exists, current issue/send guards, zero-line draft deletion and billing classification must reuse this exact request-owned fact. Complete current-owner successors add the finite predicate in their existing native order, preserving current Bank/NEXT/PP/Report/C1 hooks/signatures; they cannot trust a frontend hold flag. T0 is excluded from other invoices; D1 cannot be issued/sent/deleted; unrelated D1 Timesheets remain untouched. No Batch Generate draft selection is used to return T0.
