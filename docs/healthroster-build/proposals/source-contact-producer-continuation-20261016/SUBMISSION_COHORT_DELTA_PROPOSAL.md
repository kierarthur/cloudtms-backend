## Actual mismatch and compatibility boundary

The existing `weekly_candidate_cohorts` is already identified by Source cycle, Candidate, actual Client and manager-route hash. Its independent `current_submission_generation_id` and generation numbering are cohort-local (schema 15092026_1534 plus migration 30092026_2059). However, `weekly_timesheet_submission_requests` enforces both `(source_cycle_id,candidate_id,request_generation)` uniqueness and one active request per Candidate/cycle. The current private start owner selects the old request by Candidate/cycle and supersedes it when new scopes differ. Activating previously paused Client B would therefore retire A and restart A's question. That behavior cannot implement the pause contract.

The public `weekly_source_timesheet_submission_request_start_atomic_v1(jsonb)` returns its private owner's result unchanged. CREATED returns one real request ID, one generation ID, one clock triple, one message intent ID and scope_count. UNCHANGED returns one real original request ID, generation ID and clock triple. Preserve those shapes and meanings; do not add a public partition array, choose a representative ID or report an aggregated scope_count for one child request.

The existing public multi-client operation remains supported when all requested scopes can truthfully belong to ONE existing or new native request and every new requested scope is eligible. Reuse of a legacy mixed-client request returns its actual original generation, including when the lookup began at B and the real generation belongs to A's cohort. A public call spanning separately owned requests, partial overlap requiring multiple requests, or a paused new scope raises an explicit original-operation refusal atomically. It does not retire any existing request. Eligible B continues through private partition composition used by Import/Bulk/recheck, or an explicit B-only public request.

Actual policy `docs/weekly-source/policy-successor-20260930/04_MODAL_POLICY.json` missingTimesheetJourney prohibits adding a new scope to a sent link and prohibits resetting the original clocks. This proposal preserves every existing request's original membership IDs, request_generation, started/reminder/deadline, deep link and submission/completion receipts. It does not rebase memberships or infer a request from globally largest generation_number.

## Native owner and private composition

The complete private start owner retains its signature `(jsonb,boolean)` and original public success shapes. It validates the original request, actor when not automatic, publication, real Contract/Candidate/Client/week and Source fingerprint before any effects. Then it acquires deployment and complete sorted actual scope locks, followed by the existing Candidate/cycle import advisory lock, cohort/request/generation rows in immutable ID order. Callers must acquire deployment/scope locks before cycle row locks; any earlier publication entry requiring that prefix is an explicit integration delta, not permission to alter a Banking body.

Lookup is by actual active membership, not Candidate/cycle alone. An unchanged business scope may resolve to a legacy mixed-client request whose cohort differs from the current Client. Validate its actual generation, membership hash, current pointer and original clocks; return that original receipt. More than one owner for the same requested business member refuses as unresolved. Do not overwrite A's cohort pointer with a fabricated B generation.

When every requested scope is new, every included worker scope must pass the current pause and existing native policy checks. Choose the genuine first scope cohort exactly as the old public operation did. A single-client private child therefore has its own real Client cohort. If that cohort already owns a different active submission request, do not append scopes, supersede the old request or reset clocks: refuse that child with a truthful native scope-conflict disposition. A distinct-client uncovered child may proceed. When a fresh request is created, set started/reminder/deadline once from the real server activation instant AFTER its pause gate. Keep native intent/activation/audit writers and existing sequence/hash owners.

Add only `private.weekly_contact_source_submission_partition_v1(jsonb,boolean) -> jsonb` for internal Import/Bulk/recheck composition. It uses the same original request envelope, validates all inputs before effects, and returns a closed internal `CONTACT_SOURCE_SUBMISSION_PARTITION_V1` with exact per-client results and per-scope exclusions. Each success contains the unchanged native single-request receipt plus exact requested business membership aliases. No result declares provider acceptance. Each paused/unresolved child is excluded with its real reason and next eligibility if any; accepted/unknown original owners and native clocks are retained. Distinct children execute under the same complete sorted lock set. No all-candidate supersession branch remains.

Existing public direct calls retain atomic all-or-nothing behavior. Internal composition isolates only an explicitly enumerated expected child refusal; unknown dependency/data-integrity errors remain errors and roll back that composition. New child exclusion codes require exact Worker mapping through existing bulk result handling before mounting. A pause is not provider failure or success.
