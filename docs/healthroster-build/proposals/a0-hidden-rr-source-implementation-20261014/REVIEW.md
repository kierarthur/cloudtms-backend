## Physical arbiter and purpose

The private table stores only the token kind, actual native UUID or exact JSONB string identity, and a toggled concurrency bit. It contains no price, actor, business status, clock, readiness or replacement entitlement. No sequence, FK, ordinary persistent seeding, retention timer or token retirement is added. Service, browser and PUBLIC table/function access is revoked. Only actual native SEND/atomic owners invoke retaining mode; trigger-owned OLD/NEW values invoke ordinary mode. The primitive's Boolean is private, never a service API or a trusted client flag.

| PHYSICAL_UUID | Actual OLD/NEW reference, complete family member and genuine owner-assigned P0/R0 UUID |
| BOOKING | Actual booking text under native `btrim`; NULL skipped, empty non-NULL retained |

| ALIAS_JSON_STRING | Exact top-level string members of native alias arrays; separate from text-key equality; NULL, scalar/object and non-string members do not become identities |

The schema refuses installation unless all four native text columns are actual `text` under deterministic collations and the default collation used by JSONB's B-tree comparator is deterministic. This is required because text equality, JSON containment equality and JSONB B-tree ordering are distinct native mechanisms. The arbiter uses native UUIDs and exact strings, not a digest or invented canonical economic key. PostgreSQL 17's deterministic `texteq` compares length/content, while JSON containment uses scalar string equality and JSONB B-tree comparison uses the default collation. The new checks connect those domains without changing ordinary collation. [PG17 text implementation](https://raw.githubusercontent.com/postgres/postgres/REL_17_STABLE/src/backend/utils/adt/varlena.c), [PG17 JSONB implementation](https://raw.githubusercontent.com/postgres/postgres/REL_17_STABLE/src/backend/utils/adt/jsonb_util.c).

Ordinary larger identities are skipped only because they cannot equal a valid smaller retaining string under the checked domains; other UUID/booking/key tokens still participate. This new correction-purpose bound and actual index maximum require source/native acceptance. It is not a global input truncation or an ordinary data rewrite. ## Ordinary and correction phases

For an absent token, ordinary mode inserts then deletes only its own probe. Correction alone retains a new row or really toggles an existing tuple. Every token acquisition uses the current owner's 1 ms lock bound, restoring the previous timeout and rethrowing on failure. No lock wait is silently widened by the new helper.
