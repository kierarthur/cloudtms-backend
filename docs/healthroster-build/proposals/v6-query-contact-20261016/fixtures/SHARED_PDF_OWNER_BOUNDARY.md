This is a finite read of the actual native document path used by the query attachment owner. The exact root HEAD, source hashes and included wrappers are pinned in QUERY_NATIVE_PREFIX_INPUTS.json. It does not claim R2 access, PDF contents, native execution or provider delivery.

`public._import_review_query_evidence_core_v1(uuid)` in `21072026_1820_00_import_review_internal_core.sql` reads the actual current Timesheet source/signatures or complete signed QR/manual asset. It requires its real `current_document_version_id` to be a verified READY, non-superseded TIMESHEET document for that exact entity and `document_revision`, with real key/SHA/size/pages/timestamps. `private.weekly_source_issued_signed_query_evidence_v1(uuid,uuid)` in `13102026_1205_healthroster_issued_signed_query_v1.sql` adds the genuine signed-check-only preset, approved signature witness and actual issued invoice/FINAL_ISSUE document/import chronology. Neither owner claims that database entity metadata proves which workers occur on individual pages inside a PDF. A key shared by an included and excluded worker therefore cannot be safely attached merely because both rows say TIMESHEET.

The real per-Timesheet runtime viewer is `broker/src/invoice-async-http.js`, TIMESHEET branch around2419. It first returns the current READY version. For MANUAL/QR without a document asset, it resolves the actual latest native Timesheet evidence/manual source, requires `env.R2.head` to find the object and submits the existing `PREPARE_ASSET` command with its genuine evidence/source identity, revision, key, media type and rotation. It nudges the real DOCUMENT lane. Those are actual runtime/network effects and are not invoked by this source/SQL fixture.

The genuine operation owner is `private._invoice_operation_start_core_v8(jsonb,uuid,timestamptz)`: the `13102026_1143_healthroster_scoped_credit/..._start.sqlinc` wrapper preserves the existing non-credit owner in `27072026_1042_invoice_async_v8/27072026_1042_11_private_invoice_operation_start_core_v8.sql`. `VIEW_TIMESHEET_DOCUMENT` resolves the actual entity/document revision/template; `BUILD_DOCUMENT` is registered only when no matching READY version exists. READY documents and original operation idempotency are reused. No inspected current command supplies a proven page-to-worker map or a force-rebuild for an already READY shared artifact. Supplying a made-up template version, bumping Timesheet revision or editing a READY row to defeat reuse would not be a genuine source correction and is not implemented.

The actual planner is the `13102026_1143_healthroster_scoped_credit/..._planner.sqlinc` wrapper and retained downstream definition in `13102026_1700_weekly_source_invoice_window_receipt/12_retained_final_issue_transport.sqlinc`. `public.trg_timesheet_document_invalidate()` in `23072026_2207_invoice_queue_stage1_revision8/23072026_2207_trg_timesheet_document_invalidate.sql` responds to actual business/source changes such as worked facts, signature/authorisation, version/currentness, manual/QR and policy facts. The safe Health-owned boundary is exact: eligible-only query body rendering and exclusion of distinct native Timesheet attachments are implemented by the current native enqueue owner. A genuine existing independently verified per-worker asset/document can be consumed through the existing native evidence/document owner. An actual eligible electronic source can use the original per-Timesheet BUILD_DOCUMENT path when that owner admits it, with real worker rendering required before proof. When a current READY shared artifact is reused, or a manual source has no trustworthy worker-page ownership, query recomposition holds with `CONTACT_QUERY_SHARED_ATTACHMENT_REQUIRES_NATIVE_REBUILD`. The concrete missing owner evidence is either a genuine independently generated current per-worker document, or an approved native source/page ownership and rebuild lifecycle that preserves immutable READY history and real operation idempotency. No new PDF command, page extraction, alternate asset, Bank component or fabricated document metadata is added here.
