## One native identity arbiter

An ordinary absent-key probe uses `[X,X+1)`, where X is **the actual top-level** `pg_current_xact_id()` converted through exact decimal text to numeric. It inserts and immediately deletes only its own non-retained row. Different actual XIDs are algebraically disjoint even for a shared absent alias. A correction retains an unbounded range; ordinary probes intersect it. A visible retained token uses SHARE NOWAIT without UPDATE for ordinary work; correction alone takes UPDATE NOWAIT and changes its tuple. This is proposed concurrency state, not a duplicate entitlement, financial authority, fabricated native history version, timer or token-retirement system.

PostgreSQL 17 documents that `pg_current_xact_id()` returns the current top-level transaction identity, including inside a subtransaction. Its INSERT documentation supports exclusion arbitration with DO NOTHING and excludes exclusion arbiters from DO UPDATE. The proposal therefore uses named exclusion DO NOTHING followed by the exact retained-row lock/change; it never uses unsupported exclusion DO UPDATE. [PG17 transaction identity](https://www.postgresql.org/docs/17/functions-info.html), [PG17 INSERT](https://www.postgresql.org/docs/17/sql-insert.html), [PG17 btree_gist](https://www.postgresql.org/docs/17/btree-gist.html).
