# Existing validation-store provenance constraint

Primary26.4 requires one writer in the existing `public.timesheet_validations` store and describes `last_source='AGENCY_INVOICE_WEEK'`. The current structural source declares `last_source uuid` (`22082026_1500_cloudtms_test_structural_baseline.sql:4266`) and its exact foreign key references `public.hr_imports(id)` (`22082026_1501_cloudtms_test_structural_finishing.sql:7874`). The current weekly native writer upserts that real import UUID. Inserting the planned text, casting it to a UUID, creating a fictitious hr_import, or putting a Source publication UUID into that FK would violate the actual owner.

The minimum compatible additive design preserves `last_source` and that FK for existing imports. The SAME validation row gains a nullable typed authority discriminator (`AGENCY_INVOICE_WEEK` for this producer), a nullable genuine Source projection-publication FK and a32-byte actual week-facts hash. All three are NULL together for the existing legacy rows. Agency rows require all three; the native writer resolves and verifies the actual current publication and whole-week facts. This adds provenance to the existing store, not another validation or change store. No schema change is present in this bounded increment.

The new writer must derive status/reason from the actual complete eight-condition native week producer. `VALIDATION_OK` requires complete=true; unavailable input stays unavailable and writes an actual causal error reason rather than a false zero or fabricated pending decision. The actual validation timestamp is server time. The new Source publication column cannot replace the hr_import identity or old history. The writer enqueues the existing native TSFIN path, then a genuine native post-authorise recompute observation must prove current financial readiness before D1 return; queue absence/count alone cannot complete that phase.

Source consumer composition must cover the native weekly apply writer/reference Mode A dispatch, all override producers, Authorise/paired Authorise, Worker recompute/crosscheck readers, existing invoice classification/issue/delivery readers, actual current-row/correction lifecycle and Office reason display. Preset rows must refuse legacy validation and both override statuses through genuine native derivation, preserving other clients. A discriminator tag alone cannot grant a writer or suppress a native hold. The same planned week producer is reused by the store guard/readers; there is no second comparison engine.

The complete current-owner census and the exact producer/read-owner changes will be a separate source proposal before any additive canonical DDL. In particular, the new authorised validation lease/frame and native phase observation must preserve original financial/cash/signing identities and actual phase actor; the existing UNA-only frame cannot be reused by asserting an AUTH label. Native role/top-RPC READ COMMITTED, hidden-RR foreign-writer schedules, compiled contract and real API/UI/phone/NEXT gates remain required.
