# Candidate Contract Move native projection checkpoint

Source only. No native SQL/API acceptance, deployment, database or hosted fixture was run. This checkpoint is not the complete Candidate lifecycle closure; MOUNT_RECIPE.json records the owned follow-on work and true external producer dependencies. Root alone reviews/mounts/executes the finite payloads.

The native producer is `private.candidate_contract_move_context_v1(environment text,candidate_id uuid,timesheet_id uuid,workflow_id uuid DEFAULT NULL) -> jsonb`. It is owner-only, returns NULL for genuinely unmoved subjects, and strictly verifies a real alias/current placement/member/completed operation and exact Candidate/environment before projecting. `context.dto` is the exact 17-key CANDIDATE_CONTRACT_MOVE_V1 response. Other context keys are internal and never returned by Candidate or manager HTTP.

Native `candidate_app_timesheet_detail_v1`, page v1/v2 and `_candidate_workflow_maps_to_card_v1` now consume the accepted member association. Current B display and existing action target use actual B/Contract week; original workflow IDs/generations, immutable Contract/anchor/target, component and correction identities remain intact. History requests retain is_history even when the requested B differs from both immutable A and current C; native history actions/capabilities are cleared. Ordinary unmoved responses retain their existing shape. The exact v2 detail continues to delegate this v1 without an alternate producer.

Manager START is the existing BEGIN_MANAGER_REVIEW branch of candidate_workflow_transition_atomic_v1, after its genuine token/request/state/expiry/generation/manifest checks. It adds only the same sanitized DTO and derives the latest association on exact START replay without updating the saved mutation receipt. The existing outer Worker enrichManagerCorrection call remains untouched. The manager receives no Candidate session authority or document permission from the DTO.

Inherited source refs come from actual immutable native submission components in each exact member workflow's current submitted generation (FINALISED uses generation minus one), plus explicit same-workflow source_component_id ancestry. A generation-2 signature can therefore prove its original generation-1 upload receipt. No all-history, week proximity or neighbouring claim join is used. `kind` is the actual component_kind; `id` the actual component UUID; `version` the actual workflow_generation decimal string (the primitive allows NULL, this producer emits genuine known strings); `sha256` is the actual source_content_sha256 lower hex. Components with no source content hash, such as a generated HOURS_TIMESHEET awaiting rendering, do not receive an invented upload hash. Existing source-field immutability and rendering authority remain native.

`unchanged_facts_sha256` hashes the server JSONB textual representation of candidate_contract_move_facts_v1: version, actual worked/schedule/break/additional/reference/week facts and exact workflow IDs with current immutable_submission_json/input_snapshot_json. It excludes physical/Contract/booking identity, labels, generation/state and approval timestamps. A move or manager lifecycle advancement alone preserves the domain; a real later hours/body/native draft change changes it. It is a factual context witness, never signing or mutation authority. App reconciliation must also verify original receipt IDs/hashes and current workflow/generation independently; it must not make an old captured signature certify later edited hours.

The immutable move-time original seal is a separate domain. The actual scope stores original_evidence and from_evidence inside the already immutable review member JSON. The first original alias directly selects the first accepted review seal. Read validation checks original Timesheet/evidence fields, immutable workflow identity, captured immutable source component fields, and each real claim's before/after native event path. Generation/manager approval progression is not compared to a forever-live mutable workflow hash. A captured signed body in the same native generation must remain exact. Original claim economic/approval/refusal history is not blanket excluded; only the four already reviewed native financial-refresh columns are outside that claim domain. Repeated B→C scope derives A-anchored workflows before any current fallback and adds only actual B member workflows.

Paper status/download retains native detail authorization first, then uses only the certified evidence_origin_timesheet_id to read the original immutable pack/workflow/document version. Ordinary requests preserve the current-only read. The tested READY path does not create another pack. Genuine PREPARING task continuation for an archived original still requires its actual existing native document owner qualification.

Summary invalidation uses the existing revision sequence/table, touching original/current aliases and their genuine Contract weeks on acceptance, and actual current placement after subsequent native workflow/approval/mail change.
