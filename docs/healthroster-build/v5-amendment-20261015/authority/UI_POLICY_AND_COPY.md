## 7. Timing, payroll priority and source changes

Global manager timing is a first delay plus an ordered list of follow-up intervals, each measured after the preceding accepted send; 0–10 follow-ups, mode MANUAL or AUTOMATIC per sequence and interval unit HOURS, CALENDAR_DAYS or CLIENT_WORKING_DAYS, selected alongside its numeric value. Default: first eligible confirmed-pending enquiry at completed review (`0` delay), one deliberate Office follow-up after two client working days, zero automatic follow-ups. An administrator may configure zero or multiple follow-ups. Retain existing five-minute manual throttle; it is not the policy follow-up interval. Source settings are current data, not hard-coded prose. A deliberate additional enquiry may serve the same still-open purpose when Office judges it useful; it requires a reason, current preview and frequency check, and never resets that row's routine automatic allowance. Reimport, changed filename, new cycle/generation or unchanged status never grants another allowance.

Default routine scope is the latest one completed dated client Contract week with confirmed work and maximum work age 14 calendar days. Both the recent completed-week count and maximum age are editable global settings. Routine chase stops at the earliest applicable configured age limit or actual client cutoff, with exact date shown. Older genuine claims remain visible for Office resolution with no automatic historical campaign; a deliberate useful enquiry can use the reviewed manual exception below. Follow-up checks actual eligibility, incomplete/complete updated evidence, prior accepted sends, reply, pause, max-age and cutoff each time. The existing calendar supplies client working-day interpretation whenever CLIENT_WORKING_DAYS is selected; this revision does not silently hard-code it over the editable interval vector. Thursday priority sorts valid unresolved work; it never shortens a reply clock, forces a message during pause/quiet time, or writes off late genuine work.

Worker timing retains its separate initial request, one +6-hour reminder and +12-hour response deadline unless an approved settings revision says otherwise. Pause does not reset or extend these clocks. New eligible work held before activation records evidence immediately but starts a request clock only at its permitted activation, independently of push quiet timing; an already active request keeps its actual start/deadline. No matching-pending standalone question is added. At resume a now-expired request is Office attention; do not force an old initial/reminder pair. Emails ignore push quiet timing; source contact pause applies to both configured channels.

## 9. Final reconciled decisions and native interface boundary

This section makes the current owner choices explicit wherever earlier examples were abbreviated. Health_CODE_AUDIT.md §4 is the single move API/schema authority and §6 the single Source pay-decision wrapper authority; Banking owns the called genuine Work, correction, reservation and recovery commands. The physical native family key is `family_root_id`; `canonical_work_id` is reserved for a genuine Banking Work and can be absent for pending work. This guide never generates those financial records or calculates an offer.

**Worker says an authorised shift was not worked:** a denial against Released or final Source creates **Needs attention — Decide pay and client contact** before any automatic client enquiry. It also applies when an earlier denied Awaiting row is later authorised. Office can select **Keep Source invoicing; do not pay the worker or contact the client** or deliberately **Ask the client to check**. The latter is an explicit preview/send choice. An unchanged report never makes that choice automatically. A denied pending-only row with no independent signed/pay issue remains quiet History.

Before the final backing arrives, save the selected future pay/no-contact decision with `NO_FINAL_REPORT_YET`; show **No final report received. If the final Source includes this work, its Source invoice treatment is retained.** Do not display a fabricated invoice reference or amount. Once an accepted final report exists, show its actual unchanged Source reference/membership/amount. The decision closes selected worker checking questions as well as selected manager/Temp Staffing enquiries; unrelated questions remain. Independently signed, paid, protected, reserved, frozen and unknown outcomes use the actual §6 preview and review/resume branch. A signed financial decision retains original signatures and facts; a genuine actual-hours correction still uses its existing replacement-signature route.

**Ordinary invoice branch:** draft/on-hold work uses its original invoice editor/remove owner and legal allocation receipt. Issued unpaid work uses the original permitted unissue, remove and reissue route after exact reviewed conditions pass. Paid/protected/unissue-ineligible work retains captured invoice and opens the actual credit/correction review. A physical move can finish with `invoice REVIEW_REQUIRED`; B is excluded from another invoice until placement correction is confirmed. These ordinary owners are never Source-move delegates. Source invoicing remains fixed before and after issue.

**More is a compact dropdown**, anchored to the selected worker/client rows, containing only permitted actions. Normal choices are New enquiry, Messages and replies, Pause/Resume messages, Move Timesheet and Decide pay and client contact where relevant. Each opens one small focused review. More → New enquiry can also be a deliberate useful same-purpose follow-up: Office may need another contact because the earlier email was missed.
