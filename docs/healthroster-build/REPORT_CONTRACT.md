`public.weekly_source_self_bill_report_scope_resolve_atomic_v1(p_request jsonb)` is service-only. Its closed request keys are:

```text

report_number, invoice_date, layout, content_sha256

```

UUIDs are physical existing scope/actor identifiers. Report number is `XYOXLRddmmyy` with invoice date in 2000–2099 and layout A/B. SHA256 is hexadecimal. Pence may arrive as exact decimal integer strings and is normalized to bounded signed bigint. The function proves actual enabled F1 rules via `weekly_source_effective_rule_set_v1(client_id,cycle_id)`, dated actual client membership, active ROSTER group, cycle identity and native UPLOAD_SOURCE authority. Group locks precede cycle locks. It permits an exact FINALISED pay cycle so report acceptance can follow pay finalisation. Same-content exact-scope replay retains metadata; different content using a report number or cross-scope content replay refuses.

Each `rows` element is the same canonical DTO used by stage hashing and rederived at seal from stored rows:


Raw columns are closed to `reportTimes:{start,end,overnight}`, `requestedOn`, and `components:{net,vat,gross}`. Each component retains the parser's closed bounded evidence: coordinate, sourceKind, cellKind, formulaPresent, originalToken, decodedToken, tokenTruncated, parseState=PARSED, parsedPence, optional normalization/rounding strings. No worker/private header is duplicated into evidence. Start/end are naive local factual timestamps; overnight end uses work date+1. SQL preserves Request leading zeros and normalizes date/timestamp and pence representations before hashing. Caller-supplied alternate hashes never replace this authority.
