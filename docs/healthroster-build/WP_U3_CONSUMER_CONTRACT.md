# WP-U3 Source consumer contract and integration gates

Source-only proposal, unmounted and uninstalled. Banking owns the single public native Checklist overlay. It is part of the first-install candidate but unavailable for inspection in this lane. Root must reconcile this Source leaf and consumer with that exact installed owner; no competing public Checklist RPC, API, sidebar, query store or state ledger is supplied.

New owner-private functions in `supabase/repeatable/healthroster_wp_u3_source_proposals/`, inclusion order:

1. `private.weekly_source_actual_timesheet_submission_v1(uuid) returns jsonb` — `wp_u3_submission_context.sqlinc`.
2. `private.weekly_source_signed_submission_read_context_v1(uuid,uuid) returns jsonb` — `wp_u3_signed_submission_read_context.sqlinc`.
3. `private.weekly_source_check_only_query_rows_v1(uuid,uuid,jsonb) returns jsonb` — `wp_u3_check_only_query_rows.sqlinc`.
4. `private.weekly_source_healthroster_checklist_leaf_v1(jsonb) returns jsonb` — `wp_u3_client_week_context.sqlinc`.

All are STABLE read-only proposals with fixed search paths, logical `postgres` ownership and no PUBLIC/anon/authenticated/service_role grants. Root owns logical owner mapping, final native/public Checklist composition, generated contract and central ACL verifier. No table, index, public RPC or migration is added. Included `.sqlinc` files stay outside canonical `.sql` roots until root deliberately includes them in its reviewed chronological closure. Their repeatable directory preserves the existing include envelope. Four owner-private signatures, zero service-exposed signatures. The separate `supabase/verification/support/wp_u3_native_read_vectors.sqlinc` is fixture-dependent verification only; never include it in an install repeatable.

The Source leaf takes the actual native Checklist scope (`actor_user_id,source_cycle_id,source_group_id,client_id,week_ending`) and optional command CONTEXT/ISSUES, cursor and limit. It validates actual cycle/client/group and dated membership, then calls unchanged native Office authority for the admin or reduced pay view. Non-ROSTER, disabled or nonpreset scopes return `applies:false,preserve_native:true`. NHSP/nonpreset public output remains the native owner's responsibility and is not reclassified by this leaf. Week ending maps to a real Sunday cycle, while retaining the client's own week ending. This proposal uses a strict ended-date read (`own week < group-local current date`); root must explicitly prove C-1b/C-9c around Sunday midnight against the final installed native calendar contract before exposure.

For the signed arm, row admission comes only from actual current non-archived/non-revoked HOURS Timesheets, real submission witness, dated signed-group eligibility and corrected member selection. Actual current submitted-awaiting-manager witnesses count; device drafts, expected Contract weeks, source shadow data and Office-only P0 proposal do not. Waiting correction counts T0 and excludes P0; APPLIED excludes displaced T0 and R0 and counts genuine P0. The latest ended week with an actual submitted Timesheet is retained when complete; older weeks remain only with a real unresolved native read item. No fixed lookback is introduced. Current import-review issue generation and current validation source prevent historical email rows from keeping a completed older week open. Any unsupported native submission/legacy/source fact is a named engineering gate in the predicate, not a fabricated submission.

The adjacent signed submission read arm first proves the exact existing actual Timesheet, real immutable worker submission, Candidate, Client from actual Contract or one current same-version TF, workflow/generation, signature and work date. It uses the unchanged F1 signed predicate when available. For actual Daily with physical worked-start not yet materialised, the authorized read exception uses unchanged canonical submitted-hours projection plus the same dated native policy/effective-authority owners. It returns `SUBMITTED_PENDING_NATIVE_MATERIALISATION`, `query_route_available:false`, `actions_held:true`. This is read admission only. It cannot authorize correction/Send/manager/query/finance mutations, does not claim finalized or READY, and leaves F1's legal predicate byte-identical. Missing nullable-Contract Daily TF Client remains unproved; no booking Client is substituted. Root must prove actual worker-submit/materialisation order with native fixtures.

The signed query helper is shared by Queries and Checklist, including Daily-only scope with no weekly publication. It reads the normal current `import_review_decisions` at exact `import_review_states.preview_generation`, normal validation status/reason/last_source, normal issue/delivery-items/outbox records, waiting correction relation and exact D10 issued-signed query evidence. Pending-native Daily read rows have no query evidence/actions and do not invoke D10 eligibility. It does not call a mutation catalogue, enqueue, mark, validator or writer. It adds no discrepancy inference: issue reasons and summaries are native records. SENT_VERIFIED requires the existing successful delivery/item/outbox provenance. There is no invented send or delivery from queued state. Read-only pay users retain actual TS/correction facts for native pay-subject admission, with invoice query recipients/history/evidence redacted. Missing current issue snapshot is explicitly `CURRENT_IMPORT_REVIEW_ISSUE_SNAPSHOT_UNAVAILABLE`.

R-254 supplemental rows reuse exact native source-only `ADVISORY` records/reasons/current import generation for an own-week that already has an admitted actual submitted Timesheet. Their native action identity, source row and evidence are retained. They have no counted Timesheet, writable target or row-admission entitlement, and are excluded from the reduced pay view. No source-only record creates a signed row. Historical source advisories are excluded when a later current native import covers that own-week.

The private raw projection keyset uses `(native folded worker name, actual work date, immutable item ID)` with one actual item per Timesheet plus noncounted native advisories, maximum 100, default 50. Cursor binds actor/view/cycle/client/week/filter and the full read revision; a changed read requests `WEEKLY_SOURCE_CHECKLIST_ANCHORED_REFRESH_REQUIRED`, not a false end. This raw traversal is not the final public Checklist issue page: root's native owner must apply permission/subject selection, flatten its native issue semantics and order by native reason rank before public slicing. No independent rank/classifier is invented here. Root's main-list owner also supplies every requested main sort/direction, actor/filter-bound cursor, full row identity and anchored range refresh. The old Source scopes offset cursor stays byte-identical.

The context leaf supplies process facts, not financial labels: accepted checking upload plus ACCEPTED attempt, actual confirmed coverage, expected noncancelled base Contract weeks, completion history, separate final revision/client manifest history, exact report scope pointers, actual submitted set hash/count/latest week/earlier open week count and qualified WAIT count. Checking due is the following group-local Monday, separate from import acceptance. Unproved submission reasons remain named/count-bound internal diagnostics and cannot create a row. Current completion alone cannot stand for Acacium export pay plus report invoice. A qualified WAIT never becomes `paid=true`. Missing/ambiguous WAIT remains null with an engineering gate; the count is not fake zero. This leaf is internal; root must not serialize raw native contexts as public rows.

## Closed service projection

`broker/src/weekly-source/healthroster-checklist-source.mjs` exports the private service adapter, projection guards and browser-neutral session helper. It contains no transport, database call, command dispatch, payment math, state classifier or persistent cache. Root injects `assertActor`, the exact native Checklist `readNativePage`, and `loadAuthoritativeEvidence`. Native selection applies retention and subject visibility BEFORE keyset slicing. The Source consumer rejects a page that would need post-slice removal; it does not silently publish an empty page or false end.

The actor result is `{actor_user_id,permission_view:'ADMIN'|'PAY_READONLY',active:true}` from real native authorization. Client input is closed: command CHECKLIST/CHECKLIST_ISSUES, actual scope IDs/week, opaque cursor/anchor, sort/direction and internal limit. Actor, origin, finances, holds, targets and evidence cannot be injected in that user body.

The service frame is `WEEKLY_SOURCE_CHECKLIST_SOURCE_FRAME_V1` bound to actor/view, opaque binding hash and read revision, with bounded rows/items, truthful `has_more/next_cursor`, anchor and explicit `refresh_required/native_preservation`. Normal NHSP/nonpreset preservation returns the exact native response unchanged. Each Source row has immutable row ID/scope, route, native retention evidence, native Checked/Completed/pay-Completed status cells and counts, exact hold evidence and server-admitted No one worked/Undo descriptors. Each issue has immutable item ID/scope/route, worker/date/Weekly-or-Daily, native reason/status and permitted subject. `ACTUAL_TIMESHEET` requires actual counted TS; `SOURCE_INFORMATION` requires null counted TS/action/correction, INFORMATION subject, no pay permission and exact native action/import/source-row/evidence plus existing parent row witness, with `counts_for_row_admission:false`.

Optional `submission_read` is a closed pending Daily witness: state, actual Timesheet/Client/Candidate IDs, work date, workflow/generation, immutable submission SHA and `actions_held:true`. Root binds every identity/hash to the private native witness before serialization; the consumer additionally checks Client/scope/TS/date/generation and refuses every action while pending. It does not verify a cryptographic signature independently or manufacture native authority. The source callback must supply truthful pending labels/withholding evidence, not a finalized/READY label.

Every hold packet is closed: `holds_pay,holds_pay_scope,withheld_amount_pence,holds_invoice,pending_decision,authority`. A true pay hold requires known positive scoped pence and SHIFT/TIMESHEET scope. False requires actual known `"0"` evidence, not null or guessed zero. Unavailable withholding stays `holds_pay:null,withheld_amount_pence:null`; unknown state is amber **Decision needed**. Root's callback must obtain these values/status/sub-line from the actual same Source/NEXT/ordinary gate and qualified evidence. It must not implement a second discrepancy or payment classifier. Unknown authority never manufactures No hold or Ready.

Reduced pay users see permitted pay subjects as text only, regardless of badge: alignment, paired authorisation and permitted same-draft return remain visible; general invoice editing, credits, issuing and invoice-hold release subjects are hidden. No action links, No one worked or Undo reach this Checklist view. Such users reach their permitted pay action only at the existing actual Timesheet workspace. Checked is a dash; Completed is the native pay-only cell/count. The UI never infers permission from an invoice-hold badge.

Waiting correction's counted item is T0 but its permitted Timesheet action binds exact P0; after apply only P0 is counted, never R0. Reminder is forbidden once a waiting correction is chosen. Signed rows never acquire Finalise. Link kinds are exact UPLOAD_DETAIL/FINALISE/QUERIES/TIMESHEET/DAILY_REVIEW/UPLOAD with scope-bound targets, no synthetic URL or new modal. Root wires them to existing `openTimesheet`, Queries expansion and `openReview(importId,{returnTo})` owners. Group route labels and status/sub-lines arrive from native server evidence; Daily appears only on the issue's day.

`readTimesheetInformation` delegates the existing native Timesheet presentation and existing `applyNextPaidEvidence` V3 decoder. The consumer does not infer paid or processing hours from current/authorised/status/WAIT. Missing native informational proof stays unavailable. This lane reads the existing broker decoder, not the unavailable future Banking Checklist overlay.

The session helper uses only ephemeral existing-frame memory. Root supplies the native comparator. It merges by immutable identity, keeps loaded expansions/scroll and visible anchors, handles explicit range closure/removals and picks the nearest surviving anchor. Revision changes require anchored refresh; actor/filter/sort/view binding changes cannot reuse traversal. Each main/expansion observer is independent; collapse disconnects only that child and disposal prevents later activity. Root still must prove the installed native changed-range contract and real Office modal/observer wiring; synthetic cache tests do not prove server insertion discovery.
