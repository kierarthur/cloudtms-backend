# Correction Worker adapter source handoff

Status: standalone source only. No route or shared index is mounted; no SQL, Report source, Credit freeze, generated contract, ACL, database, Git history or hosted resource was changed by this lane. Source tests use synthetic dependency callbacks and do not prove real producer, writer, document, R2 retention or business acceptance.

The new `broker/src/timesheet-correction-orchestrator.mjs` exports `createTimesheetCorrectionOrchestrator`, `cloneFrozenCorrectionReversal` and `CorrectionOrchestrationError`. It contains no network transport, persistence, calculator, queue implementation, notification sender or storage binding. The runtime must authenticate through existing Office/native middleware before constructing trusted context. The injected `assertActor(context, action)` must reuse the real actor owner, returning only the authenticated `actor_user_id` and TEST environment; the module makes no role or client-reuse assumption. Native SQL repeats its exact actor check.

The factory returns `send`, `prepare`, `authorise`, `cancel`, `returnToDraft` and `runLifecycle`. `prepare` is an internal service operation: its frozen original finance, signature and P0 producer context must never become a public detail response. The module has no public serializer. All effects and callbacks are awaited; all request state is local to the operation.

`p_now_utc` is omitted, preserving the native server clock. The injected `rpc(name,args)` must use the existing trusted service transport and preserve native returned failure/error semantics. It must return the exact scalar JSON object, not arbitrarily pick a row from an array. Native errors remain errors. Mixed batch outcomes keep bounded business codes, without raw exception text or snapshots.

SEND accepts only `{timesheet_id,expected_version,proposal,reason,request_key}`. Proposal accepts only existing closed `CandidateScheduleSegment[]` under `schedule` and optional `changed_dates`. The break discriminant is the actual `kind` union; NO_BREAK also requires `no_break:true,break_minutes:0`. No origin, actor, invoice, finance, financial identity, target derivation or snapshot can enter from that user payload. Other request actions accept only `{request_id,expected_state_revision}`. The ordinary lifecycle item boundary accepts existing timesheet aliases, `row_key`, `expected_timesheet_id`, `expected_version` and `expected_row_signature`; it rejects client lifecycle-group hints and financial payloads.

## Injected owner composition

`buildReplacementSnapshot({prepare,actor})` must call the existing bounded canonical weekly or Daily producer/preloader with exact P0 context and existing frozen authority. It returns a complete native snapshot, not a rate suggestion or partial patch. The adapter checks exact P0 UUID/version, Candidate/Client UUID, valid issue flags, nonempty pay method, component mode and clear financial lifecycle locks. It freezes the prepared DTO before passing it to the producer so a callback cannot rewrite immutable original finance. It neither computes hours/rates nor calls a writer itself.

Root's existing finance owners are `buildWeeklyCorrectFinalServiceSnapshot` / `calculateWeeklyProtectedSnapshot` and `buildCandidateDailyAtomicMaterialisation`, with route-specific bounded inputs retained by the root integration. Existing A0/T0 finance is cloned from native PREPARE's exact current TSFIN. There is no recalculation of a paid or issued original. R0 keeps historical rates/policy/refs/clock/identity and exact component ordering; explicit approved quantity and monetary fields are sign-negated, including nonzero mileage, additional unit counts/day values, ERNI and VAT component money. Numeric strings retain decimal precision and exponent through a sign-only operation. New-leg metadata and payment/authorisation/invoice lock bookkeeping are removed. Unknown quantity/money fields fail closed. New SEGMENTS have `is_reversal:true`.

`readRequestAuthority({requestId,actor})` is mandatory for Cancel and Return and must delegate root's approved narrow service-only `timesheet_correction_request_authority_v1(p_request_id,p_actor_user_id)` owner. Required result is `{request_id,state,state_revision,replacement_timesheet_id,return_invoice_id}` from the single existing private request row; optional `ok` is harmless. It must not clone a store or return financial/signature evidence. Root owns creation, generated contract and final ACL for that approved reader. Pending signed Cancel never invokes finalized PREPARE, because PREPARE requires a finalized manager P0 witness.

`deleteCommittedTimesheetR2Keys(applyResult,options)` must be bound only to the existing root owner `deleteCommittedTimesheetR2Keys(env,applyResult,options)`. Its availability is checked before Cancel mutation. The adapter calls it only after verified CANCELLED receipt, exact P0, unique valid delete-operation UUID and committed singleton PERMANENT_DELETE result. It passes only the native final filtered `r2_cleanup_keys` plus `{deleteOperationId,requestedTimesheetId}`. No key inference, prefix search, extra key union, direct R2 delete or new retry store exists here. Native archive Cancel cannot invoke cleanup. Saved Cancel replay may resume the same existing owner with the same durable operation ID. Invalid or failed cleanup summary produces a truthful committed-CANCELLED/pending follow-up; it never claims SQL rollback or R2 retention proof. The existing owner owns durable retry recording, including truthful `durable_retry_recorded:false`.

Return has no native CAS parameter. The adapter therefore requires exact APPLIED request authority at the supplied terminal state revision, and checks the returned invoice ID against immutable `return_invoice_id`. No-op, exact empty replacement and replay are preserved. A native `return_pending:true` with `AGENCY_INVOICE_TIMESHEET_RETURNING` remains a named hold; it is not rewritten to completed.

## Complete approval receipt

Fresh approval requires request revision old+1, exact prepare fingerprint, exact original/P0/reserved R0 IDs, distinct actual TSFIN IDs, immutable original financial hash, all six authority hashes, and complete native Authorise member results (two members or exact A0/R0/P0 three). Native returned failures halt the unit. Terminal saved APPLIED replay can omit the transient `authorisation` body, but must still contain full immutable receipt identity and hashes; the adapter does not rebuild or reauthorise it. `ordinary_notification_timesheet_ids` must be exactly `[replacement_timesheet_id]` on both fresh and replayed receipts. The adapter sends no notification itself; root must purpose-bind follow-up through existing notification owners using only that P0 list and its existing idempotency receipts.

## Mixed lifecycle resolver

`resolveLifecycleItem({item,timesheetId,selectedTimesheetIds,action,actor})` must use actual existing request/native whole context, never infer correction ownership from booking or root IDs. `selectedTimesheetIds` contains only already validated physical selection UUIDs. The resolver returns null for an ordinary item; otherwise it returns `{kind:'CORRECTION_REQUEST',selected_timesheet_id,request_id,state,state_revision,replacement_timesheet_id,reversal_timesheet_id}`. A selected original A0 may join the request only with server-proved `original_authorisation_required:true`, exact `original_timesheet_id`, and exact P0 (or existing R0) selected in the same batch; it cannot apply a correction when selected alone. This avoids separately authorising A0 again after the complete request unit. APPLIED results also supply existing native `transition_items` and `expected_member_count` (two, or three with that exact original witness). Transition items must bind exact full unit IDs, versions and one server-derived correction group. Caller group hints cannot supply them. Root owns the actual read-only resolver wiring; unavailable resolver fails closed.

Every item resolves before the first mutation. Request IDs are de-duplicated, so R0/P0 aliases invoke one unit; separate repeated corrections sharing a root remain separate units. WAITING requests call the new atomic request owner once. APPLIED WHOLE groups and ordinary items delegate to unchanged native lifecycle expansion/transition plus pinned generic bulk owner through `runOrdinaryLifecycle({items,action,actor})`. `runOrdinaryLifecycle` must retain native full validation, CAS, complete-unit expansion and results. UNAUTHORISE cannot operate on a WAITING request. The result is a per-unit batch report, not a claim that several SQL transactions are globally atomic. A later failed unit does not erase a previously committed receipt or prevent an independent unit from receiving its own outcome.

## Explicit held gates

Missing A0 finance is held with `CORRECTION_ORIGINAL_NORMALISATION_UNPROVED` before any producer or mutation. A preview/calculator result is not proof of actual normalized bounded-writer output. Root is reviewing an adjacent owner-only sign-clone INSIDE the existing atomic approval after the unchanged original writer re-reads actual stored A0. That architecture is compatible: only fresh locked missing-A0 admission may omit supplied reversal; stored A0 is negated without repricing and the full batch-writer/assertion/whole-authorisation path stays atomic. This adapter is intentionally not enabled for that future DTO until root freezes the exact contract and proves it.
