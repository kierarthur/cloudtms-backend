## History page, manifest and cursor objects

Ordinary page exact keys: `version,candidate_id,work_id,section,parent_id,context_id,component_key,amount_scope,consistency,rows,upper,terminal,next_cursor`. version is PAYMENT_HISTORY_V1; consistency is LIVE_KEYSET_REFRESH_FOR_LATE_COMMIT. Candidate/work and scope/parent/context are UUID text or the permitted null. rows is a bounded array of exact `{key,data}`. key and upper are ordered tuples of the declared section key types. Data contains the section's exact fields with STRING_OR_NULL scalars. upper is null only for an empty terminal page. terminal is boolean; a terminal page has null next_cursor, otherwise the cursor's key matches the last row and its upper is unchanged.

Manifest exact keys: `version,candidate_id,work_id,sections,terminal,next_cursor,consistency,scalar_encoding,unavailable`. terminal is true, next_cursor null, scalar_encoding STRING_OR_NULL. Each of 52 unique sections is exact `section,parent,keys,fields,amount_scope,applicability`. applicability is SCOPE_QUALIFIED, or CANDIDATE_ONLY_USE_REFERENCED_PARENT for Timesheet-scope CASES/COMMANDS. unavailable is the exact ordered array MOVED_ROOT_FLAT_PAID_BINDING, CANONICAL_MULTI_CHANNEL_VECTOR, MOVE_COMPARISON_RECEIPT, GENERAL_APPROVAL_ACTOR_REASON_NOT_CAPTURED_IN_NEXT_ROWS, with TIMESHEET_COMMAND_WITHOUT_WORK_OR_CASE_ANCESTRY added only for Timesheet scope.

Cursor exact keys: `version,scope_kind,scope_id,section,parent_id,context_id,component_key,upper,key`. version is PAYMENT_HISTORY_CURSOR_V1; scope_kind is CANDIDATE/TIMESHEET with the matching native UUID scope_id. section/parent/context/component match the request exactly; upper and key use the section tuple schema. MANIFEST requests require null parent/context/component/after/upper. First ordinary pages require after and upper both null; continued pages bind both to the same validated cursor. Parent SCOPE means null parent_id; other parent kinds require the qualified UUID. EFFECTS alone requires a bounded component_key.
