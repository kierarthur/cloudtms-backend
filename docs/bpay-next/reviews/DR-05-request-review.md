## Finding — P2: null SYSTEM issue bypasses the six-code E2 boundary

Migration72–74 tests `original_issue_code in (...)` without requiring non-null. PostgreSQL CHECK permits a NULL result, so a SYSTEM RELEASE request with a null issue satisfies this constraint. Admission repeatable108–109 similarly uses `v_issue not in (...)` in its rejection IF; that NULL operand does not reject when the other operands are false. The current native worker schema permits `status='REVIEW'` with a null issue (`03102026_1324_banking_pay_next_core.sql:477–499`), so this is not excluded by the referenced row type.

Smallest fix: require `original_issue_code is not null` in the SYSTEM constraint and reject `v_issue is null` explicitly in the SYSTEM admission branch. This keeps system release confined to the owner's six named codes; it needs no additional protocol or proof store. Reported to root immediately. Source acceptance of this component remains pending that fix and final integration.
