## DP01 — pin exact native item identity and kind

The design currently gives non-null `group_key/component_key/member_key`, but does not specify the component-versus-segment discriminator or NULL-safe owner tuple. Use actual typed kind/owner FKs and a collision-free native unique tuple, e.g. WORK_COMPONENT(work_id,component_key), WORK_SEGMENT(work_id,component_key,segment_key), CASE_COMPONENT(case_id,case_component_id). A string sentinel member key must not collide with an admitted upstream segment key. Revision/line UUIDs are provenance and concurrency references, not stable economic keys. For a moved segment the old component-parent/key attribution remains separate from the new parent; use WB-36's exact union and parent reconciliation, never only the current approved child.

## DP02 — make the week predicate exact

“UK current week” needs the actual comparison, since a simple `week_ending_date>today` blocks this week's valid work Monday–Saturday. Server London business date once per transaction gives current Sunday `uk_today + 7-isodow(uk_today)`; a normal retained Sunday work week later than that is future, and `eligible_from_date=week_ending_date-6` is its first Monday. Invalid/nonstandard week evidence remains explicit unavailable unless a genuine native owner defines it. Do not use browser time, future configured pay date or UTC midnight to choose current week. This adds no clock/table/owner; WB-37 still owns later promotion.

## DP03 — close accepted-offer scope and lifecycle

“Exact live run link” needs an actual membership/phase predicate in the design. Use genuine sealed accepted selection/run command and the exact work choice/component or segment membership (including ALL), not any historical run_selection row for that work or Candidate. Actual native statuses are run PREPARING/REVIEW/DRAFT/CANCELLED/EXECUTING/COMPLETE and worker PREPARING/REVIEW/READY/DRAFT/CANCELLING/CANCELLED/ISSUED/COMPLETE (core1324:418–477; successor checks may extend them). Explicitly make `SNOOZE_SEGMENT_STALE` metadata-only: an absent/changed stable key excludes nothing and cannot itself block or wait a valid unsnoozed sibling. Pin the gate to qualified positive Source WORK/PROTECTED_WORK only; ordinary/reimbursement/Additional/nonpositive/managed negative scopes do not inherit query blockers. Future named owners remain pending rather than being presented as current installed branches.

Default eligible/included counts are legitimate server facts, but the draft should name them distinctly from actual actor/run selected membership. WB-21/22/23/25 supply later real choice state; no agency global selected_count may assert a user's current unticks merely from Ready eligibility.
