## Required design precision

1. **SD01 — Bound child capture and credit, not only the work page.** The design says bounded pages but does not specify how a selected day with many segment children/previous origin members is completed atomically or resumed. Current publisher1009 `119–130` traverses an arbitrary real segment array; current capture2018 `769–773` limits parent position rows to 100, which does not bound their segment or prior-share child sets. Record the finite child limit/cursor, exact expected child count/completion seal and deterministic key order. Capture/hold must not advance the parent cursor or reserve a partial day until all accepted included/excluded and removed historical segments are complete. A separate stable child cursor is appropriate if needed; an unbounded per-parent historical traversal or silent truncation is not. Preserve the exact accepted revision/control snapshot and real lease/nonce/cursors. The named share/balance helper must use indexed native work/day/segment/hold/effect membership, not Candidate history or repeated whole-history reconstruction.

2. **SD02 — Close missing historical gross attribution before holds.** Root design correctly prohibits guessing, but must name the actual outcome for nonzero original day gross credit lacking an exact retained segment share. Current day-level run_position/financial_effect does not prove its segment allocation; the existing investigation expressly confirms this missing authority. Require an explicit finite REVIEW/refusal/issue path before positive hold or negative collection, with the same original day/credit identity retained and no implicit zero, proportion, order/date attachment, backfill or fresh wage. Exact removed-segment negative origins must join the retained historical membership, even when absent from the new approved set. F-19 conditional genuine carryover remains a separate dependency; clean launch does not turn an unexplained existing credit into zero.

3. **SD03 — Pin stable identity uniqueness and basis operands.** Approved segments use `(revision_id,component_key,segment_key)` while R2 run membership is `(run_work_id,segment_key)`. Actual1009 validates only nonblank `segment_id`, not duplicate identity (`119–130`). State that duplicate upstream keys across the revision are rejected before seal, or positively establish the actual producer's uniqueness guarantee; do not fix a duplicate by suffixing date/ordinal. Ordinary keys remain the actual upstream segment_id; Source1548 `92–96` separately proves actual work_event_id and calculation_fingerprint. Never make the latter the segment key. For worker-pay basis, list the finite actual worker operands: stable approved identity, quantity/used rate/gross, source channel/company and worker-relevant tax/control values. Keep concurrency revision references separately. Explicitly exclude full Source HEAD/book/binding revision IDs, raw component/inventory/calculation digests and full policy/settings/rate-schedule JSON whenever their change can be charge-only. Their stored provenance may remain evidence without automatically changing the worker basis. This follows the investigation's precise charge-only requirement; it does not remove genuine worker-relevant economic/control changes from the basis.
