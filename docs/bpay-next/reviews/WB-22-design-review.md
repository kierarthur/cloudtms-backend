Design23 correctly uses genuine original component pages/seal before accepted_choice_descriptor is installed. Current1832 `bpay_next_seal_component_selection_v1:1039–1040` calls original `bpay_next_materialise_choice_segments_v1` **only when** accepted_choice_descriptor IS NOT NULL. Its1832:523–540 replay/SEALED/native component/100-key pages already derives retained segment disposition; no new segment engine, producer or money owner. ## DM02 — implicit SUBSET must participate in original positive-line eligibility

Original1832 Create448–461 refuses SUBSET if no descriptor components are selected, or if selected descriptor line lacks an actual eligible Ready item. A partial subset derived from previous actor baseline has no such raw positive descriptor entries. Merely inserting it as selection_modeSUBSET and later server-sealing pages would leave the original skip guard classifying it BPAY_NEXT_SELECTION_SIGNED_LINE_NOT_ELIGIBLE. Define its actual effective positive native line set once and feed that same set to the original eligibility test, native component append/seal and positive membership. Raw intent remains untouched for memory/replay; original old-descriptor branch stays exact. Do not create an implicit Work with zero selected positive lines; Case-only/debt/payable-parent qualification remains original.

## DM03 — dirty Keep baseline must match read defaults/counts/Create

Design29 says dirty local intent is not overwritten by another window's acknowledged baseline. Design19 returns the latest acknowledged baseline/default facts, while21 adds an explicit baseline reference only to Create and HEADER count_selection. If dirty Keep retains an older acknowledged baseline but CANDIDATES/CANDIDATE_GROUPS/GROUP_LINES return default/New-Changed against a newer header, mixed defaults and accepted positive membership can disagree even though agency/financial Workbench revision is unchanged. Acknowledgement alone does not bump current financial projection revision.

Explicitly bind those default-enriched reads to the same retained acknowledged reference when dirty intent retains it, or provide an equally finite exact reconciliation rule. One optional typed baseline-run UUID in existing W1 request/count context, validated to exact namespace/acknowledged state, is sufficient; no new route/kind/clock. Clean stores may adopt latest; dirty older stores count/display/accept against their explicit reference. A fresh local Select-all/Clear-all detaches inherited defaults and must not be confused with `null means lookup latest` in the server read convention. Every async response must confirm actual baseline/reference as well as actor/owner/context before adoption.
