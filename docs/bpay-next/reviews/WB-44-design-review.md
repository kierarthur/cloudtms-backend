3. **Make task/Candidate lock order explicit.** Candidate→work→Case→metadata→revision preholding the whole bounded page is sound and required. Also place the task row: a STEP must not hold task FOR UPDATE and then wait on Candidate control while a publication/metadata producer holds that Candidate and waits to update the same task. Read the checkpoint/page identities plainly, prehold all sorted Candidate controls and exact work/Case rows, then lock/revalidate the task before metadata/revision; alternatively prove the scheduling path never waits on a leased task row. Short CLAIM can lock only the task/epoch because it does not acquire Candidate/business rows. Fresh design now specifies plain checkpoint/page discovery, whole sorted Candidate/work/Case prehold, then locked task revalidation before metadata/revision and forbids task-before-Candidate: closed.
