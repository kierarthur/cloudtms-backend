## Required source checks within this approved design

These are concrete implementation obligations already implied by BD121, not new feature scope:

1. **NET belongs to this Case.** Join the immutable NET request's exact `run_worker_id`, `case_draft_state_id`, captured preparation and selection revisions to the exact DRAFT allocation state/instructions with this Case and Candidate. Use membership existence or equivalent exact dedup so multiple components/instructions do not multiply one NET receipt. Candidate identity, today's Case components, current worker revision or an old hold's original job alone is insufficient. A rejected/unbound source is not zero.
2. **Acceptance versus application.** APPROVED event + typed Create/edit receipt identifies an actual creation/edit; APPLIED/BLOCKED FC-10 outcome has its own completion time. Request-only or failed inputs retain truthful request/refusal labels without pretending a completed mutation. Financial effects and their exact Case event are provenance, not two sums contributing to maintained Case balances.
3. **Paging and sorting.** Each admitted heading sorts the complete native Case/report scope on the server, not an already-loaded page. Per-source bounded candidates must use the same full sort/tie and strict seek as the merged page; cursor binds parent, sort, direction and `(source,id,eventordinal)`. Preserve numeric money ordering, nullable gaps and exact text values. BD121 correctly promises live keyset reads rather than a stored snapshot. Late/backdated source commits require a fresh read as already documented by native history0653:52–57.
4. **Indexes and counts.** Reuse event2013, all-status Candidate core1020 and outcome2041:57. Add only actual Case/source/sort access paths needed by these readers; existing component/worker indexes are not automatically a chronological Case NET seek. Revised BD121:11 explicitly requires full-scope counts, the three report summary facts and count/sort footer, with unknown before server count completion; none may be inferred from loaded rows. Summary scope must match the actual admitted native report and native snooze facts. No universal index-only/constant-cost/latency proof follows from a limit or compile.
5. **Report/UI scope.** Report figures come from native maintained principal/funded/recovered/write-off/reserved/paid-credit fields and Case-kind/component remaining semantics. Revised BD121:13 makes the card-required funded/recovered/write-off/reserved facts always-visible labelled row facts, including phone key/value facts, while keeping the supplied nine headers and their server sorts. Unknowns stay null with reasons. SCR-111 is shared with later EX-50 and cannot authorise its absent Client/communication/Timesheet/payment/export features now. Preserve native context/actor/agency/epoch and Candidate view/edit/dirty semantics before every report/audit read, including eager legacy caches and retries.

BD121:11–17 avoids a separate viewer, command journal, certificate, all-history JSON/browsing array or maintained balance projection. Existing preparationPage2041 gains only the two read branches; five money-owner successors need an inverse-parent comparison for the six audit-call-only changes. These boundaries are appropriate.
