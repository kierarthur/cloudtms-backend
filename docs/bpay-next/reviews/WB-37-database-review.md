## Findings supporting PASS

- **Additive metadata only.** The migration adds nullable DUE reason with its inactive/dated constraint, an indexed native event request lookup, and two nullable native date/UUID seek pairs on the existing Workbench singleton. It adds no table, command/job kind, row data, money column or public trigger. Seek hints have no foreign keys and do not alter financial/context revisions.
- **Strict native due receipt.** The new private helper requires existing SNOOZE_CLEAR, COMPLETE, both member counts zero, nonnull seal, current NEXT epoch, no manual request receipt, command member or job (`guards:9–17`). Indexed request-ID discovery materializes at most 201 events before joins and refuses outside 1–200 (`18–37`). Every row must prove WOKEN/DUE, null system actor, exact accepted sequence/version/current native after-state, old active dated-and-due state, exact prior immutable event with nullable-key normalization, and conserved business tuple. `coalesce` is now inside `bool_and`, so an unknown row predicate cannot disappear from an otherwise true page proof.
- **Manual authority remains.** DUE discrimination now defaults to false on null (`guards:56–58`); ordinary SET/CLEAR/ACK/request operations still require the original active administrator and native command/receipt scope. A DUE row conserves the original updater, while the WOKEN event uses the already nullable actor (`69–90/113–123`). The native event remains append-only. Historical comparison inserts a null reason only where absent and preserves an explicit value (`116–117/129`). No immutable old event is rewritten. Text comparison confirms the original manual deferred receipt body is exactly retained after removing only the added DUE branch (`173–264`).
- **Required zero-job advancement is narrow.** The enroller admits only current-epoch, sealed, zero-member/no-member/no-job COMPLETE native snooze command kinds with original matching manual receipt or the exact DUE helper (`enrollment:32–48`). It advances precisely the locked next sequence and returns no job. Text comparison confirms the entire original enroller body is unchanged after removing this branch; PREPARE/expiry and financial branches are retained. The existing public enrolment service and response already support genuine advancement with null job fields, so no producer or job-kind expansion is required.
- **Bounded date discovery and control order.** Both service pages use NEXT/current-epoch ownership, closed <=1024-byte limit input, 1–200 native rows, original date/ID partial-index ordering and captured London date (`pages:16–36/134–154`). Snooze uses strict `<` and rollover uses `<=`. Distinct Candidate preholds precede ordered Work/Case preholds; native snooze preholds precede mutation. NOWAIT excludes a busy/missing Candidate scope rather than preventing unrelated Candidates' turn (`39–69/157–186`). Snooze version, active/date, Candidate and exact Work/Case identity are revalidated after preholds (`75–80`). Clock acceptance occurs after the required native preholds and before projection writes; no global projection row is locked before later Candidate discovery.
- **One truthful native command per successful due page.** The page creates one original server-owned CLEAR ID/sequence, conserves the snooze tuple, appends exact WOKEN/DUE before/after with null actor and uses the installed snooze scope trigger (`pages:81–104`). Per-scope exceptions roll back that scope's native update, event and projection together. The outer block rolls back command/clock acceptance if every scope fails, avoiding an orphan accepted command (`70–107`). Successful page completion explicitly invokes the bounded helper before returning. There is no extra full refresh or fabricated manual receipt.
- **Fair progress is durable.** Both pages persist the last visited native tuple with an exact comparison to the tuple read at entry and wrap on a genuine suffix end (`pages:108–115/203–210`). They count visited/changed/deferred separately, so a failed scope stays retryable while the cursor reaches later Candidates. Cursor-only updates do not bump the Workbench or financial revision. Exactly full terminal pages conservatively require a subsequent empty read rather than declaring omitted rows complete. Native inactive/version/event uniqueness supplies lost-reply idempotency.
- **Rollover keeps current Work and Case coverage.** The page captures its bounded original item identities before any replacement, deduplicates scopes, requalifies current due items and calls the current Work wrapper or Case refresh once (`pages:146–153/187–202`). Linked Case preholds match the wrapper's bounded native collection set (`172–180`); the original collection schema's unique case_id and Candidate FKs qualify that set. Higher-priority current processing, frozen preparation, resolution, PAUSED, hold/query controls remain with the original refresh owners. No financial revaluation, Case schedule rewrite or direct contribution delta is introduced.
- **Exposure and packaging.** The new page definitions revoke PUBLIC/anon/authenticated execution, grant only service_role, retain private owner-only helper ACLs and issue the required final PostgREST schema reload. The guard successor replaces only the two actual guard owners plus its narrowly required private receipt helper; the enroller successor replaces only the current enroller. Original snooze action/context/at-cut, command intake, financial owners and scope trigger are reused rather than reinstalled or redesigned.
