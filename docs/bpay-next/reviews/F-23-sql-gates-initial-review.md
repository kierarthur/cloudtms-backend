## Findings and smallest corrections

1. **D09 currently checks only one of four required constructs.** `assertSpecialConstructs` at 74–77 checks qualified special forms only. It permits a new `%ROWTYPE` whole-target `SELECT * INTO`/`SELECT alias INTO`, unsafe `'prefix:' || j->>'key'`, and `min(uuid_value)`/`max(uuid_value)`. Add the three finite checks to this existing source module; no new framework or money-owner change is needed.

2. **The current D09 text mask is not an executable-token boundary.** `sqlWithoutComments` deliberately retains single-quoted literals (29–51); D09's regex therefore rejects `select 'pg_catalog.coalesce(';` even though no forbidden function call executes. Quoted identifiers are flattened to arbitrary text, so a single quoted identifier containing that substring can also be mistaken for several identifiers. It has no dollar-literal/body distinction. Keep the common helper's current behavior where literal values are actually required by D07/D10, but give D09 a narrow lexer: outer routine/DO AS-body extraction using scanManagedSql source spans, executable body tokens with offset/parenthesis depth, quoted-identifier tokens, and opaque string/dollar literal tokens. Never lex every nested dollar literal as SQL. Tokenize `||`, `->>`, `#>>`, `::` as operators. Nested comments/E-string escapes and source offsets remain bounded by input. Unclosed/unclassified input fails. This is the minimum information needed for all four named checks; a general SQL parser is unnecessary.

3. **The inherited exception is file-substring membership, not the required same-signature exact-statement/count check.** At 109–112 the whole CREATE statement is skipped when identical text appears anywhere in the same base physical file. A copied full successor in a new physical file cannot inherit its old routine's unchanged SELECT statements at all, while repeated matching text has no occurrence count. A small baseline map should key by canonical routine signature from `routineDefinitions`, full executable statement tokens (including literal values), and whole-target declaration/type for rowtype checks. Consume matching base counts for each signature per current definition; changed or excess occurrence fails. Do not borrow an exception from a different function, from comments/string content, or from an earlier unrelated path. A later physical successor of the same signature can retain an unchanged statement. Require exact physical base path/enclosing statement for nonroutine migration/DO occurrences. Do not broadly exempt an entire changed routine or file.

   Actual required inherited examples are already documented in design/F-23-sql-gates.md: 1590 seal_selection, 1600 claim_prepare/pin_selected and 0360's v_period_rule SELECT survive in current0151/1958. They are not newly invented bad SELECTs. Unmatched new SELECTs must use alias.*. This avoids producer/PIN rewrites unrelated to F-23 while enforcing the source rule for newly authored statements.

4. **D10 currently accepts work after the reload.** `assertRpcReload` 78–87 requires only lastReload>lastAuthority. `RPC; GRANT; NOTIFY; SELECT 1; COMMIT;` passes its ordering predicate even though the controlling repeatable does not end with the required notification. Require NOTIFY to be the last substantive statement after definitions/ACL, with only the final COMMIT/END transaction wrapper following. Comments/ON_ERROR_STOP metadata are harmless. Current latest-root selection through definerInventory/readManagedClosure is the correct seam; retain it. A notify inside a routine/string/predecessor must remain insufficient. Do not alter shared release execution/parser semantics.

## Finite D09 implementation shapes

- Qualified special forms: exact identifier tokens `PG_CATALOG . (COALESCE|NULLIF|LEAST|GREATEST) (` in executable code, including true quoted identifier equivalents. Opaque strings/comments pass.
- Rowtype: record `%ROWTYPE` declarations per routine; a SELECT top-level INTO [STRICT] whole declared target requires one `alias.*` projection tied to its FROM relation. Bare `*` and a composite alias fail unless that exact same-signature statement/declaration consumes a baseline occurrence. Scalar field targets such as `v_job.candidate_id`, RECORD variables and `RETURNING * INTO` are outside this specific rule. No unmatching exception.
- JSON concatenation: inspect each same-depth operator chain. Reject a text extraction whose JSON left operand has an ungrouped concatenation, e.g. `prefix || j ->> 'k'`; accept `prefix || (j->>'k')`. Completed function operands such as `prefix || format('%s',j->>'k')` and jsonb_build_object are safe. An entire line containing both operators is insufficient evidence of a violation.
- UUID MIN/MAX: use explicit casts and declared parameter/local types, then simple resolved FROM-alias column types from existing saved schema/contract source. Reject actual UUID arguments; retain valid integer/text/time aggregation. A `_id` name is not type evidence (`import_review_events.id` is bigint). Unclassified new MIN/MAX arguments fail boundedly rather than silently pass. If the aggregate text result is cast back to UUID, require the same-scope native cardinality check before use; comments/unrelated COUNT do not qualify. Current changed corpus has no executable MIN/MAX calls, so no larger expression/type-inference programme is justified.
