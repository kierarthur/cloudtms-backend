## Essential finding PDR04-PE-01

**Fence failure persistence and clearing to the current module epoch.** 0533 `public.bpay_next_enroll_service_v1`, 2410–2415, checks that NEXT exists and locks the original enrolled-sequence clock, but does not retain its owner_epoch. The catch at2420–2423 and successful clear2427–2428 update the next command by agency_sequence alone. Original enrol_one0316 rejects a command from another module epoch; this new catch then records that obsolete command as a current recoverable failure. The clear can also erase its marker without a current-owner predicate. Capture the current owner_epoch under the existing shared module lock, validate the exact next command's epoch outside the caught business-step block, and fence both marker mutations to it. Preserve original N, original status and original zero-job branches; do not skip an obsolete command or manufacture its membership. A stale owner refusal must remain a refusal, not a persisted current-owner business failure.
