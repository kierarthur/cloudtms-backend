## Concrete supporting-read decisions needed

1. **Complete outer-group amounts are not stored on group.** Current group rows contain counts but no monetary subtotals. Do not reuse factual CURRENT_WORK's whole approved gross as current Ready group_amount. An explicitly indexed aggregate over current members of the <=10 selected exact parents can produce named scalar totals without history/whole-row JSON; document its child-work bound and WB10 performance handoff. If an independent hard child-scan bound is required, maintain the necessary per-group typed totals through the existing contribution/delta owner in a narrow additive supporting change. A child-page subtotal is never the outer amount.
2. **Ready count is not selectable count.** 1438:301–306 /1252:614–617 group.ready_count counts section READY, including certified empty GROUP_EVIDENCE. Such genuine zero evidence is nonselectable. CANDIDATES must test actual selectable payment/deduction membership; summary.payable_count counts PAYMENT only, so `payable_count>0` alone would omit genuine deduction-only Ready Candidates. Use the separately maintained deduction_item_count too, with the exact reason/member qualifier. CANDIDATE_GROUPS must not offer a group solely because ready_count>0.
3. **Different money dimensions remain independent.** summary.amount is READY PAYMENT/GROSS_ADD included source gross; ready_net_add_amount is NET_ADD, deduction balances are gross/net debt, selected_amount is already accepted membership, and reserved/recovery/waiting are separate. None is PAYE NET cash/headroom. Candidate amount sort uses the deliberately chosen stored source amount and never sums deductions as negative cash. unknown_amount_count>0 makes relevant complete aggregate totals unavailable (NULL), even when the known subtotal is zero. unknown_selected_amount_count independently qualifies selected_amount. Item EVIDENCE is unknown; certified empty group zero is separately qualified and nonselectable.
4. **Indexes are not all present.** Existing candidate name index omits tms_ref and explicit collation/null expression; amount and deduction sort indexes, group week/kind/UUID order, issue Candidate/Payment/Amount orders and three prefix indexes are not established by1252/1429. Native item PK and unique member tuple, Candidate-scoped item index, scope item index, group Candidate index, summary PK and scope PK do exist. Use finite shapes over their indexed scope seeds now and list exact WB10 sort/prefix follow-on indexes; do not claim WB10 timing/full-index closure or change immutable1252. Any index essential to a promised WB09 keyset bound is a narrow additive migration, not a historical rewrite.
5. **Agency and actor context are real.** Core1324:1–5 explicitly uses the protected one-agency physical database identity; module_control has no agency_uuid. Service routing and its actual agency binding must namespace the read context. Never synthesize a Source agency ID from arbitrary public rows. Cursor actor is the authenticated trusted Worker actor, not a browser override. Reuse the existing active-admin/service authority at the public wrapper and check the actual owner_epoch inside the same reader snapshot.

## Request, snapshot, cursor, bounds and refusals

Use one closed common request with trusted actor, finite kind, normalized channel PAYE/UMBRELLA/ALL, nullable Candidate/Client UUID filters, finite section/sort/direction, bounded literal-prefix search, limit and nullable cursor. Kind-specific group/reason/child selectors are named and rejected outside their allowed kinds. No date, financial amount, bank, rule/floor, target revision or Create command is a browser read authority. Choose the final exact keys once, then identical SQL/Worker/Office validators; this note does not claim a deployed key contract.

Returned cursor context binds kind, actual agency namespace, actor, owner_epoch, adoption_revision, workbench_revision, server official-pay-date context, normalized scope/filter/search/sort/direction, selector and exact last sort values/non-null unique native identity. All values and key cardinality validate before casts/JSON subtraction; dates finite; UUIDs normalized; count/version strings finite. A stale actor/date/epoch/revision/scope/sort/identity returns explicit reload/refusal, never silently continues. Page size can change without altering membership order. Empty terminal page has the same context and no invented anchor. W13's page membership/receipt obligation continues into WB21–25; the read descriptor cannot masquerade as a financial accepted-cut or persist a new F25 producer protocol.

Make each private reader a pure STABLE read so its revision, metadata, totals and selected rows share one MVCC snapshot. The public existing authority has FOR SHARE locks and is not itself a pure STABLE helper; perform that authority before invoking the single pure reader expression. Do not combine a revision SELECT in a VOLATILE wrapper with later changing snapshots for totals/rows and call them coherent. No financial clock or write-side version/adoption occurs on read. Dirty/Processing/pending fanout remains explicitly incomplete; UNSEEDED/SEEDING/ERROR is a typed unavailable/pending/error response, never ok-empty zero. CURRENT adoption does not imply dirty/task counts are zero. Point/detail readers may expose explicitly nonselectable Processing facts, but cannot call them complete or offer stale Ready membership.

NX021 (0580:25–50) is only the fixed-query/bound-value example: literal SELECT projection, fixed ASC/DESC/filter variants, `$n` USING operands; no caller interpolation or arbitrary sort SQL. **Do not copy its byte-break partial-page behavior**: WB09 explicitly requires typed refusal over the byte envelope.
