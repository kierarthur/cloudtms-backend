## Concrete gaps in the existing caller

1. **Same-method Umbrella company change bypasses the modal.** `js/main.js:280893–280900` defines isFlip only when PAYE/UMBRELLA methods differ. Only that boolean enters the dedicated modal at280975/281009. An existing UMBRELLA Candidate switching U1→U2 therefore falls through to generic Candidate PATCH rather than the required Preview/context/accepted receipt. The existing modal also rejects same method at289412–289415 before any new NEXT branch can handle it. A NEXT branch must precede that legacy same-method rejection. Compare actual original Umbrella ID with the resolved target ID, not display name or edited-field presence. Method plus company unchanged is a genuine no-op.

2. **A NEXT accepted route change would silently discard separately owned bank edits.** On acceptance281054–281056 deletes pay_method, umbrella_id **and every bank field**. The later281095–281098 repeats bank-field deletion for any routeChangeResult, on the assumption that its RPC already wrote destination banks. NEXT does not write them. Example: existing Umbrella Candidate changes to PAYE and deliberately edits own bank details; the new route succeeds but the ordinary bank PATCH disappears. For NEXT remove only route fields from the ordinary PATCH, retain deliberate bank edits and run their existing normalization. Preserve the complete LEGACY destination/deletion behaviour.

3. **Nonflip Umbrella save unconditionally clears Candidate banks.** 281080–281083 forces account_holder/bank_name/sort_code/account_number to null. This is also a bank mutation caused solely by route state. Under NEXT it must not erase the preserved own-account fields or staged deliberate bank edits. Keep the legacy clear rule in the LEGACY path.

4. **Do not solve2/3 by retaining every value in the Pay tab staging object.** The staging object already contains automatic Umbrella destination display values:
   - `stageFromDom` at285575–285582 copies all bank controls into stagedPay.
   - `clearBankAndUmbrella` at285590–285604 writes empty bank strings; pay-method change invokes it at285939, and initial renders invoke it285997/286076.
   - `prefillUmbrellaBankFields` at285651–285682 copies company banks into Candidate stagedPay.
   - company search/selection clears or replaces those bank operands at285809–285818,285840–285845,285865–285873.
   - normalization280152–280174 converts touched blanks to intentional SQL nulls.

   Thus simply removing the two deletion loops can either clear the Candidate bank on a flip or copy the Umbrella's account into the Candidate ordinary PATCH. The minimum supporting correction must keep **deliberate Candidate bank intent** apart from read-only company display/picker staging. Reuse the current Candidate/form staging boundary: preserve the actual own-account edit operands (including intentional clear) when they are entered, and do not promote a route/picker repaint into those operands. The Pay-tab display can continue showing the company destination. This requires no bank RPC, schema, new screen or policy; it is essential to the card's “writes only method/company” boundary and the owner's preserve-ordinary-bank-edits instruction.

## Smallest complete caller change

- Qualify the actual existing owner before selecting the route branch using `bankingNextOwnerClient` (5059–5074); capture actor, Candidate and exact parent frame before awaits and recheck them afterward. The established native pattern is362804–362814: fresh qualify, LEGACY explicitly returns unhandled, NEXT requires exact epoch/current actor, and unavailable/DISABLED refuses. Do not fall through to the old handler after unknown ownership or a NEXT failure.
- Existing method flip continues to reach `openCandidatePayMethodChangeModal`. A genuine same-channel different Umbrella also reaches it only through its qualified NEXT branch. Initial unknown-method/new Candidate behaviour is not broadened by this card.
- NEXT sends only target method/company and closed native Preview context/reason/operation. PAYE's destination patch is empty. Bank changes remain the separately owned ordinary Candidate PATCH, using original touched-field normalization and the ordinary endpoint. The two accepted-route deletion sites and unconditional Umbrella bank-clear site must be qualified; LEGACY keeps its old body.
- After accepted NEXT result, update current Candidate pay_method/umbrella from the **accepted native context/receipt**, not mutable requested target. The chooser may have selected another Umbrella inside SCR74. Do not force `newMethod` or the old destinationPatch back onto a different accepted target. 281021–281042 currently expects a legacy result.candidate or constructs its own fallback. Adapt only the NEXT result boundary to the new receipt; do not make it emulate old legacy queue/history fields.
- Remove only committed route fields from the remaining ordinary PATCH. Existing `removeUnchangedCandidateFields` at281166–281168 then ensures a route-only change does not create a redundant broad PATCH. If separately owned edits fail, report that the route was accepted and the other edits remain unsaved; never pretend the two calls were atomic or resubmit the route automatically.
- The existing parent save must verify its original Candidate/frame/actor after the child resolves and before mutating `window.modalCtx` or dispatching the remaining PATCH. Child closure and exact accepted target are not permission to mutate a different resumed/open parent.

## Native screen/controller reuse

`js/bpay-next-ui.js:createStandardWindowAdapter` already owns the real modal stack, geometry, header Close/Escape, focus and footer. It exposes exact active/alive/close and checks same stack identity across an asynchronous beforeClose. Reuse it; no custom modal framework or render-token workaround is needed. The current legacy modal's all-ID/canonical-history diagnostics (main289236–289239,289497+) must remain confined to LEGACY, since the NEXT typed Preview is the bounded native member/context contract, not that old proof schema.

NEXT needs the supplied SCR74 Umbrella chooser, Stays payable / Needs a decision / Not changed impact groups, immutable-protected/reimbursement explanations and Apply change. Display only returned names/facts/amounts; protected identity means safe native display/reference, not raw UUID lists. No pre-execution pay date, browser conversion, early Night-rate resolver choice or invented illustrated amount. Source and final native A4 captures remain later review checkpoints.

Use existing GET preview and POST apply routes. GET is write-free. Preview pages are <=20 rows/64KiB with a closed first context and keyset cursor; every continuation must keep that same target/context. Continuous scrolling reaches final rows without retaining an all-history array. A changed chooser target invalidates Preview and prevents Apply until the new exact target's complete scope is read.

SessionStorage pending recovery must preserve the **entire exact serialized POST body**, operation ID, Candidate, actor/owner/endpoint namespace and original context. Store before first dispatch; if persistence fails, do not send an unjournalled first request. Reopen unknown state offers only same-byte Try again, without a GET/new operation or changed target/context. Accepted receipt before clearing the pending bytes must pass the same closed validator and native identity equality. An uncertain retry's refusal must not erase the unknown command identity. Close preserves dispatched uncertainty; current-instance checks suppress late UI effects.
