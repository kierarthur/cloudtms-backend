## Required distinction

The accepted cut owns **which approved revision, selected components, Source binding/certificate/query disposition and target treatment** this Draft uses. Current locked book/position/hold/effect owns **actual realised/committed money**. Later approval/head/current-binding pointers cannot replace or invalidate the retained approval evidence. Actual money/native-book discrepancies cannot be ignored, reset or overwritten with an old snapshot. Existing Candidate ordering must keep later financial jobs behind the accepted PREPARE; a genuine concurrent money discrepancy requires its exact reconciliation, never freshness-based recapture.

Use the existing accepted_input/effective_work_cut under command agency_sequence. Retain original sealed selection IDs separately from effective approved-line IDs. No second clock, seed ledger, comparison calculator, historical sweep or F-26 epoch relaxation.

## Money and native-book conditions that must remain

- At capture/hold lock actual position; missing position is a named refusal, never an omitted member/zero. Use retained approved nominal amount to derive the offer; use actual locked realised/held SOURCE and all TARGET counters for conservation. Do not copy accepted counters back into the current book. Current-pointer changes alone are not money changes.
- Bound snapshot must require READY, exact expected monetary book revision, source_basis_channel=seed channel and the qualified native bucket equals its actual scalar realised/held amount. Opposite channel remains zero for the current supported single-channel book. Cross-basis, negative/mixed/unexplained state retains its named refusal.
- Seed paid proof keeps genuine PAYROLL_SETTLED effect, REALISED original hold, exact frozen line source/target amounts, matching Candidate/work/component/original Timesheet, settlement job and transfer/member witness. Active seed proof keeps exact ACTIVE hold/frozen line amounts. Existing live proof specifically supports unbound old frozen lines; an accepted bound line needs its own exact retained-origin proof, never deletion of the old `source_binding_version_id is null` safeguard for unrelated callers.
- ZERO means actual realised/held SOURCE and every TARGET counter are zero; exact retained component or certified removal origin remains mandatory. One point witness is not authority to zero older money or traverse history. Ambiguous multiple ACTIVE hold witnesses remain refused.
- READY guard at1246:490–518 forbids caller changes to native buckets/book revision; the actual scalar owner changes SOURCE once, the BEFORE trigger derives native deltas and increments book revision **only** when realised/held SOURCE changes. Preserve this. Approval/pointer updates alone must not invent native postings, increment money revision or break a frozen offer.
- First seed remains UNBOUND→READY once, seed_revision=1, exact original basis/witness/digest and immutable seed origin. The accepted variant must update the guard's proof dispatch and excluded metadata-field list only for that transition. READY updates cannot change seed origin, recertify or use another cut to hide a genuine money discrepancy.
- Hold inserts only positive residual, retains exact source_reserved and frozen ex/VAT/inclusive target values. Outcomes consume the real ACTIVE hold once, insert the genuine idempotent effect, decrement held/increment realised by that same amount, and mark REALISED in the same transaction. Returns/reissues stay cash authority; do not manufacture new gross, tax or WORK holds.
