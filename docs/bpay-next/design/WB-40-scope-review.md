## Essential implementation conditions

1. **Canonical rotation must fail closed.** Resolve only Work booking -> current Timesheet -> that Timesheet's current TSFIN. Never fall back to `original_timesheet_id` or a historical Timesheet's individually current financial row. A transient absence of either canonical row is unavailable, not a false hold proving readiness. The existing final1946 completeness test knows applied revision and does not itself close this public canonical gap. The builder's revised placement closes it only on new unselected AVAILABLE/ZERO portions, after saving the native `v_base`: canonical gap DATA_UNAVAILABLE priority15, hold PAY_ON_HOLD priority40, preserving stronger missing/withdrawn/Processing reasons. Accepted/reserved and recovery portions retain their native state, money and run link.

2. **Serialize on existing private locks without adding public lock inversion.** The native classifier locks Candidate worker_control -> Work. Original CREATE locks public Candidate/Umbrella FK parents and exact Work SHARE before the existing agency clock. A native hold write already owns its public Timesheet/TSFIN row before its hook reaches private Candidate -> Work. Therefore CREATE/core must use plain MVCC canonical public reads under the native Work serialization; adding Timesheet/TSFIN FOR SHARE after Work would create Work -> public-row versus public-row -> Work deadlock. Re-read canonical identity after the private locks. A hook blocked behind CREATE is a later hold; CREATE captures the old committed control. A completed hook first makes its new control available before CREATE. Do not take a new command-clock lock/increment for this retained public control.

3. **The control tuple is small and exact.** Current Work fields bind canonical Timesheet ID, financial ID, effective boolean/reason, monotonic control version and changed time. Advance only when effective control or canonical identities genuinely change. A since/updated-at-only no-op or update to a historical financial row must not refresh another Work or create a control change. NEXT-gated bindings cover genuine INSERT/hold/currentness changes and native current-row replacement on the two named tables; preserve the unrelated legacy callbacks and approval producer. If a permitted native identity move affects an old and new booking, qualify only those exact Work dependencies in stable Candidate/Work order. No history/agency scan or new broad index is needed.

4. **Version determines boundary order.** `transaction_timestamp()` may be earlier than a CREATE that a long-running hold transaction subsequently waits behind. It must not alone decide whether a change is later. Record changed time after the control locks using the existing native wall-clock equivalent, and retain the monotonic native version as the authoritative comparison operand. DR-19 receives original accepted versus current control facts; it must not infer a hold change from every canonical rotation or alter the accepted offer.

5. **Capture accepted fields once and protect OPEN choices too.** Add the bounded control snapshot to the original `work_choice` INSERT, without a delayed live substitution. Protect those columns in the final1236 guard on every UPDATE, including an OPEN SUBSET: its existing full-row comparison only applies when old selection_state is SEALED. The existing permitted component/segment page counter and sealing updates remain allowed. Skipped held Work has no `work_choice`, so any helper's accepted shortcut must preserve the captured `run_choice_member.skip_code` first rather than requiring a choice row or falling back to later live hold. Accepted descriptor acknowledgement already does this correctly and needs no redesign.

6. **Refresh through the final native wrapper.** Genuine control change advances the existing Candidate financial view and calls the current refresh wrapper, preserving exact before/after contribution replacement and native ORIGIN continuation. Its queue path already marks Processing. Do not bypass it with a direct delta write. Populate the existing item pay_hold/pay_hold_reason projection and existing BLOCKED/PAY_ON_HOLD wording/selection behavior; no new reader/transport schema or per-tick fetch is required. New skip vocabulary is `BPAY_NEXT_SELECTION_ON_HOLD`; retained historical PAY_ON_HOLD receipts remain decodable.

7. **Keep D10 retained and unfenced.** The route resolves the current Timesheet, PATCHes its current TSFIN in the existing mutation transaction and retains existing actor/admin/current-row handling and audit.
