# WB-29 ordinary and Source treatment publication

12 October 2026. Read-only source investigation after WB-45 commit `a52a45116f45785a94a17da11f23c95ed4303a4c`. No product edits, SQL execution or business acceptance. Findings and proposed support only; every runtime journey is **NOT_RUN**.

## Binding scope and conclusion

WB-29 requires a complete immutable current physical revision through the existing publisher, not a delta, and unchanged original SOURCE earnings with compatible decision mapping (card02:1095,1106,1110,1114,1127; checklist D01–03, D14–17, D21). This is feasible for ordinary and Source work. The existing Source approval/event and component book must remain their original authorities. A clone alone is insufficient: several native readers equate current/applied treatment revision with original Source approval revision. Their exact qualification needs a direct, typed treatment-to-approval association; this is necessary support for the named publisher/capture/classifier, not a new Source producer or second money owner.

The smallest proposed metadata is one nullable same-Work canonical approval revision FK on the existing immutable `bpay_next_work_revision` (proposed name `payment_treatment_approval_revision_id`). It is absent today. NULL retains every original path. A treatment points directly to the sealed original approval, never to another treatment. Repeated save/clear copies the same root from the immediately preceding qualified treatment. Thus all later reads use one point join, not recursive publication history or a later ACTIVE decision. Do not relax `source_event_id UNIQUE`, generate a synthetic Source event, alter original Source bindings/receipts, or republish/re-authorise Source inventory.

## Concrete publication transaction

1. Original W2 receipt replay precedes stale checks. Lock original Candidate/control → exact Work → native Position points, and qualify expected current and applied revision, physical Timesheet, module/epoch, target/policy/date and all finite affected native identities. Preserve the existing administrative/actor gate. No late current Contract/Candidate pricing.
2. Resolve the canonical approval: original revision uses itself; an existing treatment must contain the direct same-Work root and its genuine own publication/predecessor. The root is sealed, approved, not itself a treatment, and has the original Source event/head/financial/physical tuple. No event/head selector that chooses newest history.
3. For Source books still UNBOUND, seed through the existing owner **while the original/current predecessor remains applied**, under the original locks and exact native original effect/hold evidence. Refuse unqualified seed shapes. Existing seed proof1246:315–325 requires current/applied/Position/publication equality; no seed helper change is needed if first publication establishes READY before advancing the pointer, and later treatment leaves it READY. Do not reset or reseed a READY book.
4. Stage a whole new native revision with new IDs and next revision number. Copy every original SOURCE amount/channel/Umbrella, physical/financial, policy, classification, evidence and detail field from the qualified predecessor. For Source only, the clone's unique `source_event_id` is NULL and the direct canonical link carries its effective original event; source kind/head remain native. Ordinary retains original financial/Daily context. Copy all approved lines, five-bucket details, arbitrary schedules, shifts/breaks and approved segments through exact native parent-key mapping. Do not copy the revision worker-basis row: original segment seal1236:44–98 derives it on normal seal. Existing revision guards and complete counts remain authoritative.
5. Call unchanged-signature publisher1346 successor. Before sealing, its treatment branch verifies the root plus complete native payload equality (excluding only new row/parent IDs, revision number, timestamps and the explicit treatment link/unique event slot), including both directions of line/detail/schedule/segment membership. It does not allow a partial cloned sibling set. Original publication command remains POSITION_APPLY and native Candidate sequence ordering remains intact.
6. After the publisher has inserted the same-command publication, insert immutable WB-45 decisions with their explicit new published-line/basis mapping and SAVED events, still against the locked predecessor Position. Decision guard2100:96–101 needs this order. Return only the durable native receipt; processing and application use the existing job.

Independent sibling decisions require explicit continuation on each **own** treatment publication. Since WB-45 immutable mappings cover only one publication, a second complete clone must carry still-compatible sibling decisions as new immutable versions with the same selected operands/reason and exact current source/residual basis, then append CLEARED for superseded ACTIVE versions. Save changes only its requested identity; clear drops only its requested identity. Do not silently mutate old mapping or use “latest compatible decision across history.” Event guard2100:151–157 and deferred SAVED/CLEARED guards :163–184 support this shape, with the actual current command/actor recorded. Old accepted runs retain their pinned old ID/version even after ACTIVE becomes CLEARED. Carrying a manual amount whose old native residual no longer matches must not silently refresh/reprice it; retain its typed ambiguity.

## Feasible support versus honest refusals

Whole ordinary and qualified I1/common-HEAD Source treatment publication is a feasible named integration. No future CM owner is needed merely to publish it. Existing Source producers, canonical event UNIQUE, bindings and native book storage can remain unchanged. An unknown source rate, unsupported native partial bucket attribution, unseedable signed/old scalar shape, two-publication Source membership already refused by current capture1419:931, or incompatible physical revision is a real typed refusal, not a reason to infer rate/units, reset the book or promote a future owner. The no-HEAD PROTECTED route retains its original execution limitations (1419:889–908).

Implementation must not be declared complete with only W2 clone+decision rows: native member/book/I1 qualification and pinned quote/share parity are indispensable. No broad Source rewrite or frozen-money recalculation is justified. Existing simple/frozen downstream rows already retain explicit run line and binding IDs; change an additional money owner only if an actual exact guard is proved incompatible, not pre-emptively.
