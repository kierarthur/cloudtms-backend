## Existing runtime and failure contract

`bpay-next-background.js` already validates closed ENROLL and EXPIRY envelopes; all others pass the exact financial adapter. One delivery performs one adapter call. Continuations are published and awaited before ACK. Lost CLAIM/send waits for lease expiry; lost STEP/send retries the same original nonce/epoch/cursor, without local-clock lease adoption or a second owner call. A definite terminal CLAIM or completed/recorded STEP can ACK; arbitrary failures retry. The retained callback cannot return ACK_RECORDED without actual durable failure recording.

The minute tick gives each bounded lane a turn independently: one ENROLL, READY ≤100, LEASE_EXPIRED ≤100, EXPIRY ≤100. It waits for all sends; one lane failing does not prevent the others. At most 302 small wake envelopes can be published by one tick; this is static source accounting, not a throughput result. No recursive drain, Candidate/history rebuild or agency sweep is added. The fixed adapters bound each response/deadline and preserve exact string epochs/cursors.

`SOURCE_PAY_QUERY_OPEN` and `SOURCE_PAY_QUERY_EVIDENCE_UNAVAILABLE` are explicit PREPARE issue values in the current step schema and stored preparation-page `review_issue_code`. REVIEW is a durable non-executable result, not READY or silent success. Keep the typed issue/work identity and per-Candidate command ordering so unrelated Candidates can progress. Transient/uncertain transport issues retain automatic bounded retry. Paused retry exhaustion can reach the DLQ; no completion claim follows from that delivery state. Durable READY/LEASE_EXPIRED lanes are the NEXT rediscovery path, while F-13/F-18 own any real retained old obligation.

Reuse `wrangler.toml` unchanged: producer/consumer `test-cloudtms-banking-pay-continuation`, batch size 1, timeout 1, retries 10, retry delay 5, concurrency 2, existing DLQ; minute and five-minute crons. Local root crons remain empty. No Cloudflare resource/configuration/deployment action is authorized here. Queue phase/delay/fairness assessment belongs before PF-02; compile/source checks are not performance evidence.
