## Two concrete design traps to close before code

1. **Excluded basis cannot be invented at seal.** Original1832 accepted membership CTE filters excluded Candidate/Work IDs before run_choice_member insertion. An excluded Candidate may therefore have no retained member row; its descriptor entry is only UUID/selected, and current local Candidate untick has no member financial basis. Work/component override carries expected_revision_id, but that alone is not a Case or whole Candidate basis. For these cases, retain the genuinely accepted typed exclusion/baseline at Create using its existing native acceptance locks/version check; seal only acknowledges it. No live later seal snapshot, new command kind, new agency clock or parked F25 resolver/protocol.

2. **projection_revision is not a financial change flag.** Current1429:479–500 advances global workbench_revision and rewrites group/item/candidate-summary projection_revision for display-name/reference/bank-warning metadata-only work. Comparing it to one last-Draft number would mark unchanged financial rows New/Changed and can erase meaningful unticks. Conversely Work revision alone misses Case/control basis changes. Design must define the exact finite owner basis per kind and compare that basis; display/audit/adoption churn is excluded. A hash of names or amount alone is also insufficient.

The smallest correct design uses the two named actor tables and existing accepted descriptor/run/receipt identities. Explicit exclusions store their exact typed basis; a mode row stores the immutable accepted baseline for its scope. For NONE, explicitly explain how the server identifies new/changed *unloaded* native members relative to that baseline without a browser full-ID set or false projection-revision shortcut. If a tiny maintained selection-basis field is necessary because current versions mix metadata and economics, constrain it to existing projection maintenance and actual typed basis changes, with no producer, money-owner, command/enroller or financial snapshot framework. This precise baseline representation is the design-first gap to resolve; current sources do not already supply a safe agency-global New/Changed boolean.
