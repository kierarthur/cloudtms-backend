The decision pins native Work/based-on revision/approved line (composite FKs), physical Timesheet, component, rate family and exact code. STANDARD means the actual DAY/NIGHT/SAT/SUN/BH rate-detail row; ADDITIONAL means the actual component code, never an EX1–EX5 ordinal. The economic signature is the actual bounded JSON tuple of native source channel/Umbrella, component kind/source identity/date/unit/classification and the selected bucket's original units/used rate/source amount authority. It is not a new hash or proof framework. Independent native line/bucket/version keys avoid a wide JSON index and distinguish the full physical/economic identity through immutable FKs and guard qualification.

No reactivation. A deferred constraint requires each decision's SAVED event by transaction end. ## Exact residual and quote

The shared helper takes decision id/version, native boundary revision and optionally an exact retained run-position id, never browser money or hours. It qualifies immutable original/published basis and the actual native Position tuple. A fresh preview requires the current approved/applied boundary; a pinned run-position requires its exact captured Work/revision/component instead, with no late ACTIVE or current-revision substitution. Preparation retains its existing separate live Position comparison and money locks; frozen advice uses the original retained run-position/version or already frozen run-line amounts. Position's approved/realised/held/residual amounts must conserve. For a retained run-position, exactly preserve 1419:1300–1304: require segment_attribution_complete; use segment_included_positive_ex_vat when segment_member_count>0, otherwise greatest(residual_source_ex_vat,0)-snooze_excluded_positive_ex_vat. Excluded, unticked or query-held portions never become quote operands. Original bucket units are usable for manual mode only when this included scope is the untouched entire original scope; a narrower scope needs actual matching bucket attribution and otherwise refuses. A fresh unselected preview without retained run-position may not bypass active snoozes; it refuses until the native scope is qualified. Prior target effects stay untouched. An untouched single-bucket component proves its original units and source amount; an exact single-bucket source residual is a valid suggested-conversion operand even when remaining units are unknown. The £160 approved / £120 realised / £0 held example has exactly £40 source residual and calls 1157 on £40, retaining the previous £120 effects. It does not infer remaining units by division.

Native segment money shares do not contain per-bucket consumed units. Untouched STANDARD scope proves each bucket's exact original units, including independent DAY and NIGHT manual-rate quotes; source bucket money stays honestly unavailable unless native authority proves it, and the later aggregate must conserve the original component source total. Suggested mixed-bucket source money, incomplete source authority, partial mixed-bucket consumption, partial manual-rate units, or changed/unproved manual-amount attribution raise `BPAY_NEXT_RESOLUTION_RESIDUAL_AMBIGUOUS` until a later named owner supplies genuine retained attribution. No proportion, priority, blended rate, full saved quote or alternative earnings formula is allowed. Exactly zero residual returns a zero quote without applying the saved full manual amount. Negative residual is not a resolution quote and stays with its actual collection owner.

Only after qualification does the helper select the exact immutable policy window and call unchanged `private.pay_finance_selected_quote_v1` (06102026_1157). MANUAL_REPLACEMENT_RATE uses proved original units only on untouched eligible rate-bearing scope (including an independent bucket of untouched mixed scope); MANUAL_AMOUNT uses the exact saved amount on genuinely amount-led scope only when its included native A/R/H/source-channel tuple equals the immutable save-time original_position_basis, qualified under the original W2 Position locks. Thus an explicit £40 remaining-total decision on A160/R120/H0 may quote £40, but an old full £160 decision cannot be copied after R becomes120. No scaling or unit inference occurs. Suggested conversion uses the exact residual and honestly NULL remaining units where unproved. All numeric fields are finite, exact and bounded; manual changes require a reason. Missing source rates/units alone do not establish amount-led classification.
