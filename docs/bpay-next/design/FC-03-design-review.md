## Required implementation checks

1. Keep the original private fourteen-argument signature callable without ambiguity. The seventeen-argument owner must insert note, liability reference and preview token with the original immutable request in one acceptance. Public CASE_CREATE requires its closed token; a nullable compatibility token is not a public bypass. Later amendments remain append-only receipts. Do not accept and then update the request.
2. Compare all original inputs and all three added operands with the accepted request on replay before checking fresh Candidate channel/default floor, policy or FVR. Preserve the original active actor/NEXT gates and return the same accepted identity after later changes. Initial acceptance uses the original Candidate lock, the Candidate control lock and the original policy lock before fresh-token equality and command-clock allocation. Unknown outcomes retain the exact original bytes and command ID.
3. CASE_PREVIEW must enter before the locking page authority and perform only plain reads. The existing `bpay_next_current_valuation_policy_id_v1()` is **not** suitable for Preview: `03102026_1324_banking_pay_next_core.sql:62–73` makes it VOLATILE and takes FOR SHARE. Read the actual policy-control singleton directly in Preview; retain the locking helper for acceptance. The common terms helper must contain only the original validation/derivation, with no receipt, authority lock, ENROLL or refresh side effect.
4. Keep exact normalized entered fields and actual native owner epoch, Candidate state/channel/default floor, policy identity and financial-view revision in the bounded token. Recompute schedule terms on Apply; the token supplies equality/currentness rather than financial authority. Public optional fields are explicit null and schemas are closed. A CASE_CREATE-specific 32 KiB ceiling is justified by duplicated input and bounded notes; other actions keep their existing 2048-byte limit.
5. Preserve the nullable Case floor override. The actual live Candidate default is `public.candidates.min_take_home_wtd`; an absent default remains unknown, never zero or a newly stored override. The later Draft's original Rule B default capture remains unchanged. Validate the four-digit last-date bound before multiplication/date arithmetic, retain finite positive penny amounts and positive BIGINT weeks, preserve Credit's absence of a repayment schedule, and show principal as the total. Ceil-to-penny instalments can end with a partial instalment, so weekly × weeks is not the authoritative total.
6. Preview warnings must come from bounded current OPEN, payable scheduled recovery facts. A generic factual warning needs no aggregate of every Case; an amount would require a finite complete native scope. Exclude paused, unfunded and discharged recovery. The supplied £150 warning is a picture's sample, not evidence. Invalid or missing authority is a refusal/unknown value rather than a guessed version or money amount.
7. Apply adds only the existing WB-08 `refresh_case(case_id)` after the original FVR bump and before completion, in the same transaction. Existing apply terminal replay remains unchanged. The original ACCEPTED_PENDING_CASE receipt is not proof of completion. Read only CASE_COMPONENTS for the returned exact Case; an empty result stays pending with explicit Refresh. A failed read cannot undo an accepted command or cause automatic mutation retry.
