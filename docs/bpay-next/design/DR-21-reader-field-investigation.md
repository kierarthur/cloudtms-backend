## Request, command and job truth

The current request is the point `paye_net_request(run_worker_id,request_no=w.net_request_revision)` (core828–841 unique), with `command_id`, `entered_paye_net`, `input_kind`, `preparation_revision`, `selection_revision`, `expected_projection_revision`, `case_draft_state_id` (0380:8–24). Its command is PK `command.id`; its exact worker job is `job(command_id,candidate_id,job_kind='PAYE_NET_ENTRY')` (core967–988 unique). Do not select another Candidate's job or only the latest agency job.

- Native command states are RECEIVED/ENROLLING/SEALED/COMPLETE/FAILED (core799); native job states READY/LEASED/BLOCKED/DONE/FAILED (core974), with `phase / last_error_code / attempt_count / lease` fields. PF08 attention is a separate `needs_attention` boolean on PREPARE, not a new generic job-status token (2259 migration11–19).
- Pending value remains separate while request revision is ahead of accepted projection. Read its real command/job state and last error; do not label every unequal revision Updating forever or treat command COMPLETE as financial success.
- Exact successful Case net completion inserts projection and switches worker pointer, then sets NET state COMPLETE/net_stage COMPLETE, job DONE/PROJECTED and command COMPLETE (current `11102026_2129_banking_pay_next_case_audit_v1.sql:1274–1307`). Simple no-Case completion follows the same pointer/job/command principle in0110:142–158.
- Case financial refusal also finishes job DONE/DONE and command COMPLETE, but state OUTDATED/net_stage REVIEW with `net_issue_code`, worker REVIEW/`review_issue_code` and unchanged accepted pointer (2129:1311–1317). Show refusal, preserve the last accepted money and keep new requested value separate. COMPLETE alone is not accepted.
- Current native projection `input_kind` gives PAYE_MANUAL→Manual, PAYE_IMPORT→Sage import, CASE_PAYOUT→no payroll source. Import receipt/file/row metadata is not currently present in0380's request; DR22/DR24 own those future fields. No inferred import source/date.
