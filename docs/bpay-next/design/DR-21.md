## Frozen labels and indexed address

A genuine surname is not stored on work_revision. Parsing a display name or reading today's Candidate in the post-Draft reader would violate the exact contract. Add three nullable label fields to private.selection_candidate (captured display name/reference/surname), populated once by a BEFORE INSERT trigger on that private selection table at original member admission. This is display evidence only, not accepted economic input or a new producer protocol. The original run/Candidate primary key makes replay retain the first labels. Existing rows without that capture use an immutable selected work_revision's display/reference; their missing surname stays unknown and Candidate/worker IDs remain the stable tie-break. No historical surname is invented and no live label fallback appears in the worksheet.

The reader accepts exact run_id, literal PAYE, nullable candidate_id filter, query (0–120 characters), sort, nullable after and limit1–100. Frozen surname then Candidate ID and run_worker ID is the default Candidate order; nulls last, same ID ties in both directions. Display/reference search belongs the same reader, never a first-page Candidate dropdown. The cursor binds actor, owner epoch, run review state, maintained PAYE totals revision, maximum native agency_sequence of the current exact PAYE requests, filter and ordering. Independent investigation found the existing totals contribution unchanged at first requested input: its greater native agency sequence anchors that first transition without editing the existing totals/money owner or adding a counter. Job-driven row status needs the same maintained totals revision: one private job display-transition trigger advances only totals_revision for its exact current PAYE request when requested/applying/failed/done stage changes. APPLYING derives from the first native attempt, never transient lease renewal. No money value, reverse Run/Candidate/Work lock or new clock is introduced. REFUSED derives from the exact worker/NET outcome or failed job; a command-only enrollment problem remains a pending REQUESTED input, never an invented financial refusal. A changed binding returns a named Refresh refusal, never joins pages from different snapshots. Null monetary keys sort last. Eight header columns sort the entire server scope; child lines have their existing fixed business order.

Supporting indexes stay on private native labels, Run-worker membership/amount/state, exact projection and request pointers, and completed state/result/instruction joins. Monetary values spanning allocation results are computed in the one scoped reader, with residual server ordering and stable keyset, as the existing joined frozen review reader does; no second maintained financial summary, cache refresh protocol or loaded-page sort is introduced. The design must document which indexes support each join/key rather than claim a joined calculation is a directly stored monetary key. Two-second and150-worker acceptance remain future authorised app checks, not a source-only performance assertion.

## Financial row truth

Use the exact frozen captured preparation/selection revision's completed DRAFT allocation state. Earnings before gross deductions = captured_work_gross plus allocated_gross_additions; payroll gross is worker.gross_inc_vat after allocated_gross_deductions. Never subtract the recovery twice. With no Cases use the native frozen worker gross and captured lines, not a fabricated allocation state.

Gross-stage Overpayment and taxable Manual Debt amounts come from completed DRAFT results joined to the exact captured instruction. Payment Advance repayments and non-taxable Manual Debt are NET-stage. Show actual accepted NET allocations when the current non-retired completed projection has its completed NET state, otherwise show the DRAFT reserved recovery separately. Expose gross-stage and NET-stage Manual Debt facts for the required workings rather than losing them behind the two main legacy deduction columns. Amounts are server values, not browser formulas.

Accepted net/cash/source come from the last completed accepted non-retired projection addressed by the worker's net_projection_revision; pending requested amount is a separate immutable exact request_no lookup at net_request_revision. Numbers may have gaps. Current command/job/allocation facts distinguish NONE/REQUESTED/APPLYING/ACCEPTED/REFUSED. Never use pending input as accepted cash. PAYE_MANUAL maps Manual, PAYE_IMPORT maps Sage import only when the real accepted projection says so; no import writer/receipt field is fabricated before DR24. Unknown net/cash/source remain null; literal saved zero is ENTERED_ZERO.

Applicable payroll workers have captured lines or positive frozen payroll gross. A mixed run's genuine zero-line/zero-gross sealed positive NET_ADD payout basis is PAYOUT_ONLY and excluded from net completeness. Pure Umbrella/payout-only scope refuses BPAY_NEXT_PAYE_WORKSHEET_NOT_APPLICABLE. No live Case balance, current Candidate pay method/rate, or reallocation is read. DR37 later adds its refusal-detail field and replacement semantics; this item does not build those early.
