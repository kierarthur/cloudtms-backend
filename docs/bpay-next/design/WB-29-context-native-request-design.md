## Closed request

Use the proposed common identity and incoming-intent shape. W1 has one early closed `RESOLUTION_CONTEXT` branch on the existing `public.bpay_next_workbench_page_v1(jsonb)`, retaining service/admin/NEXT admission and native actor injection:

```text
resolution = {candidate_id, works, reason}
work       = {work_id, expected_revision_id, rows}
row        = {approved_line_id, rate_family, rate_code, intent}
intent     = null | {resolution_mode, manual_replacement_rate, manual_amount_ex_vat}
```

Every key is explicit, including nullable fields. `intent:null` requests native context and disclosed saved state without manufacturing a selected choice. A non-null intent is an explicit Preview request, not a typing-time call. The only modes are the original native `SUGGESTED_EQUIVALENT_BASIS`, `MANUAL_REPLACEMENT_RATE` and `MANUAL_AMOUNT`. Suggested has both manual operands NULL; manual rate has only the rate; manual amount has only the amount. Native mode admission remains authoritative.

Use the same identity and intent validator for W2 `RESOLUTION_SAVE`/`RESOLUTION_CLEAR`, with the existing request UUID/readback/action envelope. W2 adds the exact W1 common `context` and, on each row, `expected_decision_id`/`expected_decision_version`: both NULL means W1 disclosed no decision; both present mean the exact disclosed pair. Derive those pairs on W1; never accept a caller's pair as W1 authority or replace it with a newer ACTIVE lookup during W2. SAVE requires non-null intent. CLEAR requires null intent and an exact existing clearable decision pair; a suggestion is not a decision to clear.

Reason is a nullable bounded string at resolution scope, shared by the explicitly submitted changes. Require a nonblank reason for either manual mode, within the current quote owner's2000-byte encoded limit (`octet_length`, not character count). Suggested/CLEAR do not acquire an invented mandatory Reason control; retain the existing finite audit reason when no user reason is supplied. Validate JSON types, finite numeric range and rate six-decimal/amount penny precision **before** casting into the native numeric domains/composite. NULL/blank is not zero. Reject extra keys, duplicate Work IDs and duplicate `(approved_line_id,rate_family,rate_code)` within a Work, unsupported family/code/mode combinations and empty scopes. Exact native canonical Additional codes are not renamed or truncated.

One Candidate, user-explicit Works and at most100 total decision rows are sufficient for current WB29 one/many support. Keep the existing full W1/W2 encoded32KiB request limits, W1 SQL120000-byte response limit and resolution receipt32/64KiB variant. Count and encoded-size overflow must refuse, not omit rows or expand scope. The private2217 receipt can retain its validated flat `request_body.works` representation; the public envelope need not duplicate it. Exact replay comparison must still include the complete original action, actor, Candidate, context, reason, identities, decision pairs and operands.

WB31 requires intentional-zero confirmation. Return a literal per-row `requires_zero_confirmation` for a qualified selected zero rate/amount or zero selected result, distinct from an unavailable NULL. The smallest W2 support is a resolution-level `zero_confirmed:boolean` recorded with the original request, default false in the caller; require true when any submitted qualified selected choice needs it. That confirmation covers the exact disclosed row set and values, not a later expanded linked set. W1 Preview does not require consent. WB31 later supplies the actual confirmation control; this operand neither fabricates a click nor authorises a separate command/proof protocol.

BD160: Incoming manual operands are decimal **strings or NULL**, never JSON numbers: unsigned plain decimal, no exponent/leading zero/blank/sign, rate less than10^12 with at most6 fractional digits, amount less than10^16 with at most2. PostgreSQL checks these raw strings before casting into the native composite; the original receipt preserves them. W1 DTO numeric facts use native decimal text. The bounded six known per-row objects (original basis, Position, available rates, suggestion, incoming Preview and saved quote), and each one's actual quote object, project number scalars to text only after native qualification/calculation. Display/transport validation never computes money. W2 rederives the same exact DTO context and native basis separately under locks.
