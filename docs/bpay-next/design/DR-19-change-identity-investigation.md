## Immediate required support

The existing WB40 `pay_hold_control_version` is not an effective-hold-only identity: current trigger0611 increments for canonical physical/financial row rotation as well as `(pay_hold,pay_hold_reason)` change. Original choice0426 freezes this same mixed version. A version-only comparison can invent a hold change when both effective states are false; ignoring it when canonical IDs differ can miss a real clear/re-set. The smallest supporting change is one monotonic **effective** `(bool, held reason)` change identity on existing Work, advanced inside existing0611 only for an effective tuple change, with its value captured immutably by the existing Work-choice INSERT guard. An optional last-effective-change timestamp is display metadata, not the comparison authority. No public trigger, history table, protocol, money or producer change is required. Historical choices need NULL baseline, not default zero presented as captured evidence.

DR19 starts at original accepted Work/Case membership, not delayed run_work/Case instruction creation. Use native run_choice_member and immutable expected Work revision; do not recapture at PREPARE or Confirm. The original memory `CASE:<component UUID>` basis already supplies rule/status/due/snooze identity. Case/component revision or balance alone is not a valid later external cause because this Draft advances them during its own reservation.

Native pause/edit receipts and typed Case events/instructions supply applied external causes. Their applied/completed causal identity and owning Run must be checked before labelling change; an accepted request or own reservation is not an applied external financial change.

## Original hold cut and initialization edge

Authorized six-argument Create2223:536–541 inserts every non-skipped accepted Work choice/query snapshot before return, including OPEN component upload. Its earlier Work SHARE locks are at214–220; original held Work is skipped at477–482. Therefore the existing0426 choice guard is early enough for descriptor Create; no new membership trigger, global memory producer or delayed PREPARE refill is needed. The same guard can also be called by later legacy append, which is not a substitute for the accepted descriptor baseline. Keep A5's descriptor-only boundary.

Run.created_at_utc is core transaction_timestamp(), not exact accepted admission time. A last-effective-change clock compared only to it can count a change before the actual accepted cut. Frozen counter inequality is exact and survives clear/re-set without relying on current true state or last timestamp.

0611 reads stored Work.pay_hold but0426 captures live canonical TF bool/reason. WB40 Workbench classification reads live TF without synchronizing stored Work fields. A9 skips the public edit if native Candidate control is absent. No native worker_control DELETE/TRUNCATE writer was found in managed NEXT repeatables, and accepted descriptor choices are unheld; these facts reduce the initialization risk but do not constitute a stored/live equality constraint. Counter advancement must handle the first later actual canonical set even if stored tuple was stale. For a same-canonical TF UPDATE, OLD/NEW effective bool/held reason is retained direct evidence; qualify exact Work/current physical membership before using it. Do not treat arbitrary non-current financial edits as effective changes. If initialization is needed, keep it in the existing named control support with established lock order. Do not introduce a Work SHARE→UPDATE normalization inside choiceguard: another Create can already hold Work SHARE while waiting on the first Create's command-clock UPDATE. New valid runs must not silently degrade to NULL hold evidence because this edge was omitted.

## Ordering and bounded access

Use accepted_choice_command_id→bpay_next_command.agency_sequence as the original descriptor economic order. Qualify applied later native command sequences against that cut; use actual cause command for hold transitions, since system RELEASE may reuse a PREPARE job but2129 explicitly records the request command first. Create2223:237–245 refuses earlier pending commands/jobs and serializes the original command clock. A request/job identity alone is insufficient without applied receipt/event and exact owner.

Do not require occurred_at_utc > Run.created_at_utc as a prefilter for this exact sequence comparison. Native event defaults use transaction start; Case EDIT events deliberately store request.accepted_at_utc rather than application time. A command admitted later in a transaction begun earlier can therefore have a timestamp before the accepted Create. Root should either use an equally exact indexed native seek or add only required retained cause-sequence metadata/index on the existing immutable event/effect/transition sources through private insert support. There is no existing universal indexed Case/effect-by-command-sequence column. Do not claim a timestamp index or LIMIT1 makes an arbitrary sequence residual filter bounded; do not scan all agency commands or all old Case history. Untyped historical events lacking a genuine command link remain unavailable, not false no-change.
