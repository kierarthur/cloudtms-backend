## Recommendation

Proceed with the narrow existing-owner design. The complete approved card and all seventeen checklist rows support D08, D10 and D15, with the other rows serving as shared-owner context. Existing immutable Case LEAF evidence, native accepted membership, CASE_PAGE / CASE_SEAL, the original money locks and row allocation kernel are sufficient. No new table, command, read kind, financial owner, producer freeze protocol, parked F25 resolver or estimate is required.

The immutable accepted choice must bind non-money Case identity, rule version, status/due and controls. Outstanding, realised/reserved balances and period capacity remain live under the original locks. Full Case/component revision equality would reject legitimate money changes and the allocator's own writes; retain the recorded revisions as evidence rather than use them as a blanket current-revision fence. Old accepted runs whose richer Case basis is absent must fail truthfully through existing review/unbound handling rather than silently adopt a later rule. The ordinary non-memory route retains its predecessor behavior.

The approved NEXT card's default recovery selection and on-demand estimate contract must not be replaced by the legacy per-click headroom behavior described in the older Bible sections 6–7. Policy X remains intact: this change is confined to the accepted pre-Draft choice and original preparation owners; post-Draft consumers continue to use immutable instructions/artifacts.

## Essential source checks before local compilation

1. **Bind captured rule ID and revision to one native immutable rule.** In the first saved `11102026_0102` source, LEAF `rule_id` still comes from `workbench_item i.rule_id`, while `case_rule_revision` comes from `cr` joined through `case_component cc.rule_id` (lines 23–24 and 40–41). The enriched Case cut should use one exact native rule pair or explicitly prove projection/native equality. Mixing an older projection ID with a newer native revision can produce a truthful refusal for a legitimate accepted Case. Preserve the existing Work basis.
2. **Reject missing numeric revision/control evidence explicitly.** Key presence accepts JSON null. The first saved retained-cut gate has casts followed by `<1` / `<0` (0102:319–331); null casts can yield a null predicate and fail to reject. Root has identified and is tightening this. Positive Case/component/rule revisions and a nonnegative control sequence must be proved, with malformed/missing input using existing `CASE_INPUT_UNBOUND` handling. No whole current Case/component revision equality is needed.
3. **Check retained rule taxonomy before using its parameters.** Current component and final instruction FKs already bind kind/subtype/tax to their rule, so the DB safety fence is present (`0300:103–104`, `278–280`). Once preparation deliberately removes current component-rule pointer equality, an explicit retained-rule kind/subtype/tax match provides early truthful review instead of a later generic FK failure after period/resolution work. This is a small existing-consumer check, not a new rule owner. Genuine funding evidence and existing period-transition rules remain mandatory; a later funded rule is not a substitute for the retained accepted rule.

The first saved 0102 accepted-empty implementation is appropriately narrow: it requires the accepted descriptor, exact selected Candidate, zero retained CASE_COMPONENT membership, no Case header and no allocation state before delegating to the existing no-Case owner (149–155). Its matching completion exception retains a positive captured Work line, exact `line + managed` position count, expected/captured managed equality and no incomplete managed capture (786–797). Keep these together; merely dropping 1630's position/line equality would be unsafe. Nonempty all-false manifests remain on the original sealed zero-instruction allocation path. Case selection revision stays zero only for the genuine empty path.

The no-Case weekly fact's accepted-descriptor floor read from `selection_candidate` is necessary (0102:850–855). It must retain the ordinary live-Candidate fallback, genuine zero/unbound semantics, exact contribution owner and original projection checks. Do not treat a missing captured Candidate row as permission to fetch a new floor.

## Bounded CASES continuation

Extend only the existing `WORK_CHOICES` `accepted_inputs` variant with optional closed `member_kind`, default WORK, and a private four-argument helper. The CASE_COMPONENT variant walks the already immutable global member numbers in pages of at most 100; WORK request/response shape remains unchanged. Register the exact new helper definer, private ACL and caller closure. Worker and Office strict schemas need the same bounded fields; no new public read kind is justified.

Each Case row needs retained native Candidate/component/selected identity and exact uploaded-child evidence. Native per-Candidate header facts need run/Candidate/selection revision, status, page/item/selected/excluded counters and expected membership counts. A count alone is not a scan cursor: CASE_PAGE accepts any retained member order. Validate uploaded child selection against the retained boolean, then skip exactly those members rather than assuming the first N global members were uploaded.

Persist only one input page plus its index/cursor, current Candidate/counters and a read-ahead page boundary. Seal a Candidate before starting the next Candidate; terminal global membership proves when the final Candidate may seal. Never manufacture an empty CASE_PAGE or successful zero-item seal. After CASES, enter GUARD only; later DR owners retain guard/enqueue ownership.

The old choice-submission journal accepts pending CASE_PAGE / CASE_SEAL, but its current dispatch does not adopt Case counters (`office:499–500`, `569–585`). Upgrade only a previously valid old schema, retain original descriptor/run/command, pending bytes/hash and request UUID, and keep deliberate identical-byte retry for unknown mutation outcomes. After the pending outcome is resolved, adopt the native header counters and uploaded child facts; do not initialize zero then add a replay receipt. An old saved cursor is reusable only if its original authority is proved; otherwise restart the bounded native member walk at zero. A definite read failure retains position. Do not use the separate shell journal's all-accepted-component arrays as this continuation's membership owner (`office:707–748`).

## Controls and presentation

Use native ROW Case basis and GROUP_LINES child identities for component ticks. A CASE outer presentation key has no component UUID and its basis is null; do not synthesize a UUID or treat a representative/visible DOM row as complete membership (`workbench:571–575`). Local intent writes use the existing shared actor/agency/epoch/date choice-store namespace, so Case-only intent survives Candidate switching without a mutation on every click. Defaults and explicit exclusions come from the existing actor memory over complete eligible membership, including unloaded pages. Candidate exclusion still dominates subordinate intent.

The final common reader is 2340, the final public reader is 0008, and final descriptor Create is 0005. Add `case_state` through those existing closed projections and matching transport schemas. Reuse the final 1946 PAUSED → WAITING/CASE_PAUSED projection; PAUSED stays visible, grey and unselectable. Retained Ready membership must never contain paused/blocked components. Reuse E6's deductions-only Candidate exclusion/count behavior and `Nothing to pay` state. Positive credits/payouts remain distinct from collection.

WB24 owns complete parent/group NONE/SOME/ALL controls. WB26 cannot claim that a partial child page represents the parent Case's full scope. WB27 owns the single allocation-plan extraction and actual estimate; until that exists use Show estimate, without background amounts or browser headroom. The later GBP 0.00 recoverable label consumes a real estimate only. Remove the old Current Case facts / Add / Seal controls from the maintained Workbench journey without deleting unrelated factual readers/history or the independent shell indiscriminately.
