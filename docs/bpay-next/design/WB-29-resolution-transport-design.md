## Exact incoming scope and scalar types

The W1 `resolution` object has exactly `candidate_id,works,reason`. Each Work has exactly `work_id,expected_revision_id,rows`; each row exactly `approved_line_id,rate_family,rate_code,intent`. All UUIDs are canonical lowercase. works is nonempty, <=100, distinct Work IDs; every rows array is nonempty, <=100, with <=100 rows across the request and distinct (approved_line_id,rate_family,rate_code) per Work. Scope order remains original, not sorted or expanded. READ admits intent=NULL; otherwise intent is exactly `{resolution_mode,manual_replacement_rate,manual_amount_ex_vat}`.

Families are STANDARD/ADDITIONAL/ADJUSTMENT. STANDARD code is DAY/NIGHT/SAT/SUN/BH. Additional is actual native uppercase/btrim canonical code, 1–245 characters; other admitted code is 1–256 characters. Do not substitute EX1–EX5 or normalize arbitrary codes, Reason or financial input. Native btrim is not JavaScript's broader whitespace trim; source qualification remains native. Reason is explicit NULL or a string <=2000 UTF-8 bytes; manual modes require the same native nonblank qualification. Suggested has both manual operands NULL; manual rate has only replacement rate; manual amount has only amount.

**BD160 exact-decimal refinement:** manual operands are canonical decimal strings or NULL, never JSON numbers. Rate regex `^(0|[1-9][0-9]{0,11})(\\.[0-9]{1,6})?$`; amount regex `^(0|[1-9][0-9]{0,15})(\\.[0-9]{1,2})?$`. These preserve original native rate<10^12 and amount<10^16 ranges without Number, rounding, truncation, epsilon or a lower monetary ceiling. Reject signs/exponents/leading zero aliases, blank and excess precision before native numeric/composite casts. Preserve the validated original text for later W2 replay. The three modes are SUGGESTED_EQUIVALENT_BASIS/MANUAL_REPLACEMENT_RATE/MANUAL_AMOUNT, with no new mode.

For outputs, use canonical finite decimal text at the six finite native DTO projections (basis, Position, available, suggestion, preview, saved quote), nested quote and decision manual operands; native actual numeric arithmetic stays in SQL/1157. No generic recursive conversion/parser protocol is required. Source physical version becomes positive integer text too. Decimal equality/order/sum checks may use exact scaled integers or digit strings, solely for validation. Never use Number/parseFloat for money/rates/units or derive price/units/converted values in Office. Literal NULL remains NULL; zero text remains known zero. Derived quote.rate may exceed the manual-rate input range, so preserve actual finite nonnegative <=6-decimal text within response budget rather than impose the manual input ceiling on an arithmetic result.
