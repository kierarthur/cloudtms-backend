## Closed input and receipt

Keep public request keys exactly actor_user_id, action, args, readback, and Worker request keys action, args, readback. Propose resolution args with only request_id, candidate_id, context, works and reason. No quoted money, supplied units, browser Source amount, inferred source channel or source-bucket share is admitted.

Context is the exact native W1 offer context: agency/module epoch, selected official pay date, Workbench/adoption/financial-view currentness and target channel/Umbrella/VAT. Names must match the existing typed control contract; do not manufacture a parallel context. The forthcoming RESOLUTION_CONTEXT branch returns the authoritative identities and original/suggested/selected values separately, without seeding or mutating Source. It is required implementation support, not a new route.

Each Work has actual work_id, expected current/applied based_on_revision_id and a nonempty rows array. Each row has approved_line_id, rate_family, rate_code and the exact expected decision ID/version pair, or both NULL when the disclosed context proves none. SAVE additionally has one of the three existing modes and the two mutually exclusive nullable manual operands. CLEAR identifies only its exact disclosed active decision. STANDARD is the closed five native codes; ADDITIONAL retains arbitrary real captured codes; amount-led components retain their existing native identity. Reimbursement fixed amounts never enter conversion.

Validate raw manual text before numeric cast/typmod: finite nonnegative rate, at most six decimals and existing numeric range; finite nonnegative penny amount and existing amount range. Preserve these original validated operands in the receipt. Manual decisions require the card's nonblank bounded reason. Suggested/CLEAR need no invented mandatory Reason control: use the finite native audit reason when no user reason is supplied. Existing decision/event reason constraints still apply.

Use one Candidate with a user-explicit finite set of Work/components. Maximum 100 decision rows in total, with distinct exact identities and a nonempty Work set no larger than that bound; enforce encoded bytes as well as count. This admits one/many WB29 components without prematurely building WB30 discovery. WB30 later supplies its complete disclosed linked/excluded closure; its eligible NEEDS_DECISION members cannot be dropped merely because they are not Ready. W2 may not infer a linked scope by scanning a whole Candidate/Contract or silently expand the submitted set.

A narrow action-specific receipt extension is necessary for that real multi-row result: resolution request_body <=32 KiB, result <=64 KiB; preserve RETRY_WORK_JOB's original 4/8 KiB limits and five-field constraints exactly under its discriminator. Discover existing generated CHECKs by audited expression, not a guessed name. Resolution variants allow job_id NULL; allow work_id NULL only for an explicit many-Work request/result. A single-Work resolution retains its real Work ID. Do not insert a fake PREPARE job. The original public 32 KiB request ceiling includes its envelope, so validate the full encoded request, not only args. The response must be separately bounded by the existing transport decoder.

The immutable result identifies action and each actual Work, predecessor, published revision, child publication command, native agency sequence, logical requested changes and carried decision IDs/versions. A genuine no-op has no invented publication/sequence. Processing/completion comes from native adoption authority; it is not a promise of immediate Ready. Return the exact bounded affected set and native completion identity needed by WB34, rather than making the browser rediscover scope.

## Replay, locks and transaction order

1. Service/NEXT/admin admission and closed schema/byte checks remain native. Read the original receipt by request UUID and compare actor, action, Candidate, original epoch and the entire validated request. Exact original replay/readback precedes fresh scope/currentness checks. A replay does not adopt a newer epoch or new intent. An absent readback returns the existing not-received shape and performs no seed, publication, refresh or clock allocation. An exact receipt is immutable even when current Work has since moved.
2. For a fresh mutation, acquire the existing Candidate control and **all explicit Work locks in native UUID order before any Source seed, Case refresh or publication clock**. Recheck the receipt under that serialization point. Acquire the relevant Positions and any finite related Case parents using the existing order; do not begin Work2 locks after Work1 has caused a Case/clock lock. The existing refresh_many related-Case bound and queue semantics remain authoritative. Explicitly refuse an unproved oversized prerequisite set instead of taking an unbounded lock/history walk.
3. Under these locks qualify the exact current/applied revision, physical Timesheet version, current target/channel/Umbrella/VAT/date/policy, approval/seal, actual need or compatible manual resolution, all expected active decision pairs and actual A/R/H/residual/snooze/query scope. Qualify the original Source book tuple by sourceproof1246/native seed authority; UNBOUND is seeded only if that exact authority is sufficient. READY is never reset. No history sum substitutes for native Position/book balances. Validate caller context before own seed/refresh effects can advance it; do not reinterpret a stale original context as a new offer.
4. Before mutation, qualify and quote the full requested set plus every compatible active sibling that must carry. Build all complete old-to-new component/line mappings. Count the full physical revision tree with an overflow sentinel and cumulative encoded budget before stage; no truncated clone. Stage all finite Works and validate their complete SOURCE payloads before the first publisher allocates a global command sequence. All prerequisite Work/Position/Case locks have already been taken.
5. Publish each Work once through the existing complete publisher and actual POSITION_APPLY child command. Retain every generated child identity in the one original W2 receipt. Child commands are for native publication, not extra Worker kinds. The publisher's current/version/seal/root and original processing-barrier checks stay unchanged, and its global clock remains after business locks.
6. After actual publication has supplied command/member FKs, retire an old version in the guard-required order: insert its CLEARED event while ACTIVE, then set it CLEARED. Insert a replacement/carried immutable decision with its exact new published line/basis and child command/member association, then insert SAVED. The 2100 guard still requires the original Position basis while POSITION_APPLY is pending; do not force Position forward to make insertion pass. The same transaction rolls back publication if any later event/decision check fails.
7. Carry each compatible sibling to the same new complete revision with unchanged selected mode/operands/reason and a proven compatible exact residual basis. CLEAR logically removes only the requested bucket/component; compatible siblings receive explicit new versions, not silent disappearance. Never carry through an unrelated native revision or refresh an old manual amount onto changed A/R/H. Ambiguous or incompatible siblings cause an honest whole-request refusal before publication. Do not weaken the event uniqueness to hide contradictory historical target variants.
8. Insert the original immutable action receipt only after all child publications, events and decisions succeed; run the existing same-transaction targeted refresh/adoption path. Persist the real affected Processing/adoption outcome. No partial success receipt is fabricated for a failed atomic SAVE/CLEAR. Original receipt-based unknown recovery retains the identical request, including child identities allocated by the accepted transaction, and never resends a newly generated intent.

All existing Expected/current/applied/lease/Position checks retain their own meanings. A treatment's original Source approval differs legitimately through the explicit qualified root link; this is not grounds to bypass E2's changed-offer release. Original Source event stays unique on its sealed root. Accepted Create pinning is at the existing descriptor Work choice admission even when memory_baseline is absent, with the already-held Candidate channel/Umbrella/VAT and pay date. Historical NULL attachments never perform a late ACTIVE lookup.

## Required exact suggested/manual quote support

The existing 2100 live wrapper requires current/applied/Position == boundary at lines253–255 and a persisted decision. Therefore W2 must validate an incoming intent **before publication** without a dummy decision, and must not call that live wrapper on an old boundary after its own pointer change. The small private helper takes the already-qualified native basis, native Position or frozen run-position scope, policy window and typed incoming intent. The existing decision wrapper merely obtains those same authorities and delegates; estimate/hold/advice then use the same quote path once. Keep 1157's ERNI/VAT/channel formulas unchanged.

Normal untouched STANDARD multi-bucket suggestions are required. Native rate_detail contains each bucket's exact approved_hours and source_pay_rate; the parent approved_line owns SOURCE gross once. Ordinary approval1530:313–325 and417–432 stores those used rates/units independently of the parent gross. Source segment authority1236 also proves their captured membership. These are real native economic inputs, unlike a proportion of parent gross or current Contract rates.

For a complete untouched component (realised=held=0 and included=approved), qualify every positive native bucket and its actual used source rate, native schedule binding/approved charge rate and selected immutable policy. The same shared 1157 helper can quote a bucket's native units/used rate in its original channel with MANUAL_REPLACEMENT_RATE as an **internal Source-value qualification only**, then quote that exact bucket Source value with the actual SUGGESTED_EQUIVALENT_BASIS intent and policy. This internal arithmetic call does not relabel the persisted user choice as manual. Sum the qualified bucket Source values once and require equality to the one native parent SOURCE gross before attributing them; do not copy the parent gross into every bucket. Target ex/VAT/inc aggregation must be the same shared-quote output used by the subsequent valuer, with no new currency, margin, ERNI or VAT expression outside 1157. Preserve the selected per-bucket result and exact full-source reconciliation in the shared helper so W1 and W2 do not compute it differently.

If native totals use rounding that prevents exact bucket attribution, this must be distinguished from a missing code join. First inspect the genuine sealed used-rate/units and native component gross. Do not repair a penny mismatch by spreading a remainder, dividing parent gross by hours, pro-rating, changing SOURCE earnings or introducing a new Source producer. A genuinely inconsistent/insufficient split is a typed attribution refusal. It is not a blanket refusal of every full five-bucket STANDARD component: the exact normal reconciled path above must work, including mixed suggested/manual selections and arbitrary Additional codes.

Manual replacement uses only the bucket's exact available native units and explicit selected rate via 1157. Amount-led MANUAL_AMOUNT applies to the exact saved native remaining scope; its original Position tuple must match, and a narrowed snoozed/selected scope cannot scale it. A partially realised/held multi-bucket component lacks a retained per-bucket R/H attribution in current 2100; no formula can infer each remaining bucket from whole-component money alone. Admit a partial multi-bucket case only if an existing exact captured native segment/bucket scope actually proves those remaining units/Source amounts. Otherwise preserve typed residual-ambiguous refusal. A genuine zero included amount remains an actual zero, not unavailable.

Root's concrete refinement is a private STABLE input_quote helper taking an in-memory native component_resolution composite, boundary revision, server-qualified native Position basis and included SOURCE. That is a suitable narrow seam: unsaved intent never becomes a dummy DB row, and the original persisted-decision wrapper retains every live/run-position/native identity guard before delegation and adds the actual decision ID/version after the quote. The helper requalifies actual sealed basis, target, immutable policy/window, mode and operand invariants. Raw precision/range validation must happen before filling any numeric typmod/domain field in that composite, not after an implicit cast has rounded the value.

A single positive native bucket can have a provable remaining **SOURCE-equivalent** unit basis without claiming those units are literal remaining worked hours. Require source_rate>0, unchanged used rate, full native units whose same shared SOURCE quote equals parent approved SOURCE, and exact equivalent_units=included_SOURCE/source_rate. The quotient must itself fit the admitted six-decimal precision/range and be <= the native full units; its SOURCE penny roundtrip must also equal included SOURCE. Do not first round/truncate a repeating quotient to six decimals and then accept it merely because round(units*source_rate,2) passes: £1/£3 can produce .333333 with a passing penny roundtrip while a high target manual rate magnifies that approximation into different target money. No residual/approved ratio or target amount is used to obtain units. Multiple positive buckets remain unproved without independent native allocation. Shared helper reuse ensures this single-bucket qualification is identical for the unsaved intent and persisted live/frozen quotes.
