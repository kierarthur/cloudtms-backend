# Weekly imports: report-first journey review

Status: approved for implementation by the user, 1 October 2026. Implementation and verification are in progress; the mockups are not deployment evidence. Examples are illustrative, not TEST observations. This direction replaces the earlier file-history and Complete-tab proposals.

The controlling 2 October decisions in `../WEEKLY_SOURCE_QUERY_FINALISATION_DECISIONS_20261002.md` supersede any conflicting wording here or in the illustrative journeys, especially manager/candidate disagreement, manual send-back, the first-authorisation gate, report selection and contextual protected pay.

Latest approval clarifications: tabs are the single navigation entry to each section; remove duplicate Review queries / Review checks / Manage questions routes. Open remains for a specific record's details. Source removals and their consequences are identified automatically and disclosed in the finalisation review for Office confirmation, not left for manual calculation or manual reversal. Magnit uses the same settings-governed automatic contact policy, without deriving authority or timing from the brand name. MyTMS must retain the exact notification destination through authentication, open the hours question without an alerts-list detour, and show meaningful request-specific copy. Broken loading screens, dropdown behaviour, disabled-tab behaviour and duration-only source acceptance are included in this implementation, not deferred as cosmetic work.

## Review rules

- **R01 Authority:** one Imports hub, two server-resolved business journeys: Client system decides hours; Signed Timesheet decides hours. The selector filters eligible work; it cannot change a client/contract's authority. Daily and ordinary no-import work keep their existing routes.
- **R02 Current work:** source-authority Imports lists current accepted checking/prepared files for still-open work, not rejected, superseded or completed files. One compact upload outcome remains visible immediately after failure, with the actual reason and correction action; rejection must not disappear silently. Persist all underlying evidence for audit without displaying an upload archive. Partial finalisation hides only completed client/report portions, never another client's unfinished work. A newer checking file invalidates any superseded preparation under the existing guards.
- **R03 Report history:** after confirmed source-finalisation success, remove that client/report from active Imports and Finalise, add one immutable completed report in History, and show a success link to it. Remove the Complete subtab. History lists client, source, finalisation period, report reference where applicable, finalised time/actor and View report. It is not a file/event list. Report detail contains actual finalised shifts, source-specific movements, totals, and audit evidence. Preserve prior revisions, dedicated correction flow and explicit zero-return completion records. Never manufacture an NHSP report number for non-NHSP work.
- **R04 Independent outstanding work:** finalisation does not resolve hours questions, protected pay, pending approved-hours actions or recovery work. Those remain in Queries and link back to the report in History. Unanswered questions alone are not structural/financial blockers. A failed/uncertain finalisation stays visible as Result needs checking until read-back proves its result; no optimistic move to History.
- **R05 Compact Queries:** one group row per existing candidate/client/period/recipient-route authority, with Problem, Progress and Next action. Preserve manager-route distinctions even when display names match. A group with several issue kinds says Multiple; never conceal a missing shift behind Mismatch. One compact Open button, with expansion through candidate/chevron. No Manage questions. Expanded rows are a real aligned table, not text with appended buttons. Candidate/manager decisions and timestamps are visible in detail; no response may be inferred from message delivery. Group selection is outreach only; shift selection is acceptance only. Header checkboxes, continuous scrolling, server-wide sort/type-to-jump and restored scroll/filter state remain.
- **R06 Accept hours:** expose the existing server-authorised acceptance command for the exact eligible source-authority shift(s), with a before/after confirmation, actor/reason as required by its existing contract, stale checks and audit. Never fabricate a candidate signature or edit immutable source/approved financial facts. Protected-pay reconciliation remains its distinct existing action, not a side effect of ordinary acceptance. Hide acceptance entirely on signed-Timesheet-authority work.
- **R07 Automatic contact:** accepting a checking import starts eligible missing-timesheet and discrepancy requests automatically subject to settings, account eligibility and existing policy. Keep 6-hour reminder/answered manager tranche, 12-hour signed-query silent remainder, missing-timesheet exception, genuine manager-direct override and manual cooldowns unchanged. Candidate confirmation does not mean immediate manager email in every case. No-repeat semantic rules and stale-answer guards remain. UI copy must distinguish requested, delivered, answered and next action. Meaningful in-app question wording must not weaken push privacy policy.
- **R08 External NHSP query:** the next action means Office signs into NHSP and uses NHSP's query control for that booking so its manager can amend it. CloudTMS may show/copy booking and discrepancy details and open only a verified configured destination; it must not claim to submit a query to NHSP. A proposed Record queried action is an Office note with actor/time, not proof of NHSP acceptance. A manager saying Corrected stores their reply/intended hours; an accepted corrected import is still required to confirm the source change. Manager System correct / Did not work decisions retain their existing incident effects and separate protected-pay tasks.
- **R09 Finalise:** only explicitly prepared actual finalisation reports. Ready / Blocked counts describe report readiness, with shift details behind the report; zero tabs are disabled, select a nonempty tab automatically. Review one or multiple eligible reports, identifying every excluded blocked report. Separate replay-safe client/report commands; never merge financial ownership or partially finalise a blocked report. A normal hours query is not counted as a finalisation blocker. NHSP actual backing report and cutoff rules remain. HealthRoster early eligible-row finalisation is permitted; mixed non-finalised rows require explicit exclusion acknowledgement, with reversals separately disclosed. Never extend this exception to Magnit by naming alone.
- **R10 Time:** use one shared source/client/period filter across source-authority tabs. History defaults to the selected/recent completed period; offer actual period/date selection rather than 4/13 stored-cycle counters. Label this week's configured cutoff independently of older selected reports, and show older missing client/week finalisation obligations separately. Hide zero counts. No source cutoff on signed-Timesheet checking.
- **R11 Signed Timesheet journey:** use Imports / Checks / Ready, not source Finalise or finalised-report History. Only complete worker-and-manager-signed Timesheets are compared. Incomplete records show Waiting for completed Timesheet and link to existing workflow. Mismatch: existing manager-correction route, no candidate hours question, no accept-source, no protected pay. Exact one-to-one matching and equal total break duration permit reference write. Auto-authorise only if enabled and all existing whole-Timesheet conditions pass; otherwise use existing Office authorisation. Reference-required-before-pay defaults Off; preserve effective override. Completed records remain in Timesheets and their existing audit, not invented finalised reports. Proposed presentation retirement: remove a current roster from active Imports after all relevant comparison/reference tasks complete; no Finalise action or new financial state. A closed-period source-authority checking-only upload similarly must not force another finalisation solely to clear a file from a list; retire it only when its comparison work completes and preserve outstanding query links.
- **R12 Safety and clarity:** authority, source eligibility, omission/reversal scope, rates, invoice authority, signed evidence, Banking Pay and all existing mutation owners stay unchanged. Fix the app accepting a duration-only source break without demanding invented break times; preserve signing and server validation. Repair legacy loading/error truth and dropdown stability before release. No new external-system automation is implied.

## Deterministic design source

`journeys.policy.json` supplies the screen copy, example data, flow stages, transitions and rule references. `render.cjs` is a generic local screenshot renderer. Screens are rendered from the JSON; no PNG is hand-edited. Each image shows successive states, not four modals the user must open simultaneously. `evidence.json` records the policy digest, image digest, viewport and overflow checks. The examples show different permissible outcomes; they are not claims about Kier's actual response.

Run `node docs/weekly-source/policy-review-20261001/render.cjs` from the backend worktree. The renderer uses the existing local Playwright runtime and Chrome; it does not connect to TEST or use credentials.
