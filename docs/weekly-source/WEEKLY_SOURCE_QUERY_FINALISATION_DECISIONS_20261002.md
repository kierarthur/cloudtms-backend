# Weekly source Queries and finalisation: approved 2 October decisions

Status: controlling successor for the narrow conflicts listed below. It amends, but does not replace, the 15 September controlling implementation pack, 30 September import/query amendment, and 1 October report-first journey review. Existing Banking Pay economics, invoice authority, signed-Timesheet authority, Policy X, and pay-run operations remain unchanged.

## Boundary and period

The source finalisation period is the configured source/client cutoff cycle. A report can contain work from older calendar weeks; its period must never be inferred from a shift's Monday–Sunday work week. The candidate's existing weekly Timesheet/pay identity continues to use its contract/work-week key. These two keys must not be conflated.

Only an explicitly prepared, current import-authoritative final report appears in Finalise. NHSP previously released files are checking evidence only. HealthRoster and other same-format exports remain checking evidence unless Office explicitly chooses Prepare for finalisation; only the approved HealthRoster profile may finalise early, subject to the existing source-finalised/exclusion rules. Multiple eligible client reports may be selected in one Office action, but each retains an independent finalisation command, invoice owner, receipt and failure result. A blocked client is excluded and disclosed. Non-import-authoritative roster remains a separate signed-Timesheet Checks/Ready route and never gains source-hour acceptance, protected-pay or source finalisation through this amendment.

## Queries and first authorisation

An unresolved source-hours discrepancy holds the existing whole candidate/contract/work-week Timesheet at **first authorisation**. It does not itself block finalising a structurally valid source report or invoicing according to the accepted source. A synthetic missing-Timesheet request is not a discrepancy incident and does not block first authorisation by itself; it retires from active Queries after the applicable final source is finalised, without inventing a worker signature. A genuinely unresolved hours issue stays in Queries after source finalisation. Source changes after finalisation follow existing corrections, not an overwrite of finalised evidence.

The database command that performs first authorisation must enforce the same open-query gate atomically, not merely render a disabled button. It must lock/check the relevant family under the existing Timesheet authorisation transaction and refuse an unresolved issue. If first authorisation already occurred, opening a later review must not pretend to retroactively hold or reverse pay; existing adjustment/protected-pay mechanisms and audit govern subsequent decisions.

An Office user may send an **exact existing imported shift** back to Queries from a checking import detail, a current Finalise report detail, or a completed report's History detail, where that work identity is available. This creates one audited, Office-only manual review keyed to that existing work event, source row/version and candidate/contract; it does not create a second payable shift or automatically contact a candidate/manager. Its Problem is **Manually queried** and its group/child row is red while open. Before first authorisation it uses the same first-authorisation hold as any open hours discrepancy; if that Timesheet is already authorised, Office must use the existing unauthorise route (when permitted) before opening a pay-holding review. The user can close it only by explicitly accepting the currently displayed imported hours or protecting pay on that same work identity; stale or absent source cannot be accepted. A later import for the same durable work identity updates the hours shown in the open review, and acceptance is bound to that new source-row hash so old displayed hours cannot be silently accepted. Both decisions record actor/time and preserve the source and signed Timesheet. No new pay pathway is introduced. A later materially changed source/candidate version requires a fresh decision; an unchanged reimport cannot recreate a resolved query.

## Candidate and manager disagreement

Candidate and Manager progress are distinct, compact fields. Show **Candidate contacted** or the precise reply, and **Manager contacted** or the precise reply, with a short relevant UK-local date/time tooltip on hover/focus. Do not call delivery a response. When a candidate says their own hours are correct and the manager says the current source is correct, the hours query remains open and red. Its Next action is **Speak to candidate**. Office then chooses either **Accept current source hours** or **Protect pay** for the existing shift to close it. Manager correction still requires an accepted corrected source; merely recording an intended correction does not resolve the source difference. All other existing contact settings, manager-direct overrides, 6/12-hour policies and semantic no-repeat protections remain.

For NHSP, **Query in NHSP** means Office signs in to NHSP, finds the booking and presses NHSP's own query control so its manager can amend it. CloudTMS does not send an NHSP query. The UI may give the booking reference and record an Office note, but that note is not proof NHSP accepted a change.

## NHSP final source charge decisions (3 October successor amendment)

This section supersedes only the older Plan 6 instruction that a valid NHSP `MISMATCH` or structurally valid `ZERO_SOURCE_CHARGE` can never be accepted at finalisation. The final NHSP backing report remains the authoritative invoice source even if its rate card or contract charge is wrong. After confirming the candidate, client and contract, Office may explicitly accept the *current report's* source charge for one, several, or all affected physical shifts. The existing server-owned acceptance must be bound to the current projection, source row, contract/rate and policy fingerprints, recorded with actor/time, and independently rechecked under the whole-report finalisation lock. It never changes candidate pay, timesheet hours, source pence, or the invoice amount. A later corrected complete NHSP report is a separate correction with physical negative/positive movements; an issued invoice is not silently rewritten.

Each current final-report shift appears **once** in Finalise: in Blocked while an eligible charge decision is outstanding, and in Ready only after that decision and every other finalisation blocker are cleared. A shift with several problems remains one Blocked row, showing the issue count and the highest-priority next action: resolve candidate/client/contract or structurally invalid source data first, then review and accept the eligible source charge. The Blocked row expands in place to compare source Commission, Total Cost and total with the selected contract's calculated charge and difference. Acceptance is a compact, explicit audited confirmation, not a second warning table or an automatic side effect of finalising. Pre-final NHSP files may show the warning for checking, but cannot accept a final charge. `UNVERIFIABLE`, mixed-sign/invalid source money, missing Contract/rate or other structural blockers cannot be accepted through this route. Finalisation remains atomic per report and unavailable until all its rows are ready; candidate-hours queries independently retain their existing first-authorisation hold.

## Screen structure

Queries is one compact list, with one group row and aligned expandable shift rows. Red shading means an unresolved pay-holding issue; green means a non-blocking missing-Timesheet request or already agreed protected hours. If any relevant shift is red, its group row is red. Do not rely on a separate Pay can authorise/Pay on hold label. Office checks are separately labelled Report blocked where applicable. The user can Open for replies, exact candidate/imported hours, booking and eligible actions; no duplicate Review queries or Manage questions navigation.

Finalise has only Ready and Blocked, automatically selects a nonempty tab, and disables empty tabs. It lists only pending reports. A header checkbox selects all eligible visible reports; the action is **Finalise selected eligible reports**, followed by a confirmation/cancel step and per-report results. Open shows exactly that report's shifts, no second week selector. Completed reports leave Finalise and active Imports and appear in History. History lists finalised client/source/period/report reference/date/actor, filters by a real period or date range, and Open shows the full immutable per-shift source, pay/invoice movements and totals. Previous reports are not an upload-file archive.

A contextual **Protect pay** action for an existing imported shift fixes candidate, client, contract, date and work identity; only approved pay hours/break (minutes) and reason are editable. It labels the comparison **Imported NHSP Shift**, **Imported Roster Shift**, etc. A separate global **Add protected shift** route chooses candidate/client/contract and hours when work is genuinely absent from source, including when no file or Timesheet exists. Neither route duplicates an existing payable shift.

Meaningful MyTMS weekly-hours notification copy and one-tap deep link must be preserved across login; navigation shows immediate pending feedback and must not await mark-read network completion. Accepting source hours with a duration-only break must not demand an invented break start/end. The existing privacy and signature validations remain.
